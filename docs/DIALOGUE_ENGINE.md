# DialogueEngine: research, boundary, criteria and result

Pass 27, 2026-10-28. Written before the code; the result section at the end records what was built and measured.

## 1. What already owns quests and objectives (evidence, and the decision)

Read in the source on 2026-10-28:

| Owner | What it holds | Where |
|---|---|---|
| ScenarioEngine | Scenario objectives: `ObjectiveDefinition` with dependencies, `ActivateWhen` / `CompleteWhen` / `FailWhen` conditions, success effects; status `Locked, Active, Completed, Failed, Abandoned`; endings; `FactDefinition` / `FactValue` (boolean, integer, string); the one condition grammar `ConditionLogic` (all, any, not, compare; depth 8, 64 nodes) | `ScenarioEngine.Contracts/Definitions.cs`, `ConditionLogic.cs`; evaluated in `ScenarioEngine.cs` lines 213 to 222 |
| SimEngine | Company objectives (`sim.objectives`): predicates that observe the world, lifecycle, `ObjectiveStateChanged` event, forwarded by the director bridge | `Standard/Objectives.cs`, `ObjectiveContracts.cs` |
| nobody | A story: who says what to whom, what the player may answer, a journal text for a quest stage, a narrative flag | |

Decision: **objectives (the statuses of goals) stay where they are; DialogueEngine owns what no one owns, the narrative layer on top.**
- A *quest* in DialogueEngine is a narrative journal: a list of stages, each with a localisation key for the journal text, and rules that move the quest to another stage. It stores the current stage and a status (`not-started, active, completed, failed, abandoned`) and nothing else. It never stores or copies the status of an objective.
- A quest stage rule reads an objective through an **external fact** (`ext.objective-hold-bridge-status = "completed"`) supplied by the host each time. The host maps `ObjectiveStateChanged` or a ScenarioEngine fact to that fact; the dialogue layer does not know which engine it came from.
- Dialogue can *cause* things only by raising a **signal** (a name the host handles: start an objective, give an item). It does not change world state itself.
- The condition grammar is **not** reimplemented: the dialogue and AI engines read, validate and evaluate conditions through ScenarioEngine `ConditionLogic` (wrapped by `EngineCommon.Conditions` for strict reading). One grammar, one owner.
- Duplicates avoided: no objective status in the dialogue state; no second condition language; no second fact type.

## 2. Research (searched 2026-10-28)

Primary sources reached are marked P; where only secondary sources came back that is said.

- **Ink (inkle).** P: the runtime documentation ("Running your ink", github.com/inkle/ink, `Documentation/RunningYourInk.md`) states: save with `story.state.ToJson()` and restore with `state.LoadJson()`; observe variables; external functions are declared `EXTERNAL`, bound by the host, and separated into pure functions (`lookaheadSafe`) and actions; the story advances with `Continue()` until no content remains, then `currentChoices` and `ChooseChoiceIndex`. Secondary only (a troubleshooting article and an `inky` issue): a save is tied to the compiled story, and editing the story (adding or removing a choice or gather) can make an old save fail to load, so stories are versioned with saves. I did not find a documented seeding API for Ink randomness.
- **Yarn Spinner.** P: the localisation documentation (docs.yarnspinner.dev, "Assets and localization", 2.5): every line carries an ID tag (`#line:1a64a5`), tools add the tags, a strings file cannot be generated unless every line in every script has an ID, string tables are keyed by that ID, and a line provider fetches the localised text and assets for the player locale from the ID. I did not reach its variable-storage documentation in this pass.
- **Twine / Harlowe.** Not reached in this search. From general knowledge, not checked: passages with markup, and variables saved with the story history. I use nothing from it.
- **Dialogic 2 (Godot).** Secondary only (game press and addon pages): timelines of events (text, character, choice, condition, signal, jump), characters with names and portraits, variables. Not checked against its current documentation.
- **Articy:draft.** Secondary only: community exporters from Articy JSON to Godot; no official Godot path found. Not checked against Articy documentation.
- **Dialogue System for Unity (Pixel Crushers).** Secondary only (the product listing and forum answers): conversations chosen by Lua conditions and quest states, a quest log, save/load; runtime variables belong to the loaded database. Quest states in its documentation (unassigned, active, success, failure, abandoned, plus derived ones) are from memory and not checked; my model uses five statuses of my own and says so.
- **Localisation.** Secondary (Mozilla localisation blog): Project Fluent lets translators supply only the plural forms their language needs, where gettext requires all of them; Fluent uses CLDR to decide the plural categories (zero, one, two, few, many, other); selectors branch on a number or another value. The ICU MessageFormat plural syntax is `{count, plural, one {...} other {...}}`. I did not reach the CLDR plural-rules table itself, so the rules I implement are written from my knowledge of it, limited to whole numbers, and the locales I implement are named; anything else is refused, never guessed.

## 3. Adopt, adapt, avoid

| Source idea | Decision |
|---|---|
| Ink: the story state is one serialisable value; the story advances one step at a time; choices are presented, then chosen | **Adopt.** `DialogueRuntime.Next` / `Choose`; the state is a plain value with a digest |
| Ink: a save is bound to the compiled story | **Adopt, strictly.** The save names the digest of the document it was taken from; a different document is refused unless the host asks for a *reload*, which has its own checks |
| Ink: external functions as pure functions versus actions | **Adapt.** Reading the world = external facts (pure, supplied by the host before a step); changing the world = signals (events out) |
| Yarn Spinner: lines are IDs, text lives in string tables; all lines need IDs | **Adopt.** A document holds keys only; `LocaleCoverage` refuses a locale table that misses a key and a document with literal text |
| Fluent / CLDR: plural categories chosen by a rule, translators give only the forms they need | **Adopt** the categories, **avoid** gettext all-forms and a full Fluent implementation. Messages are a string or an object of categories with `other` required |
| ICU: arguments in braces | **Adapt.** `{name}` placeholders only, checked against the arguments a line declares |
| Dialogic: timelines of events | **Avoid.** Nodes with explicit `next` give a checkable graph; no implicit sequence |
| Dialogue System for Unity: Lua conditions | **Avoid.** A scripting language is a second owner of rules and not deterministic by itself; the shared condition grammar is used |
| Quest log with states and journal entries per stage | **Adopt** as the quest model; **avoid** storing objective status (section 1) |
| Articy / graph editors | **Not built.** Authors write the strict JSON; an editor can export to it |
| Implicit defaults (an empty condition is true, a missing variable is zero) | **Avoid.** Every reference must resolve; a missing external fact is a refusal |

## 4. Layer boundary

- `DialogueEngine.Core` (pure library): format, validation, runtime, save/load, localisation, quests. No clock, no file access, no Godot, no world. It sees the host through `IFacts`-style inputs (a dictionary of external facts per call) and `ISpeakerCatalog`.
- `GameRuntime.Dialogue` (game layer component): requests as events, answers in `Update` in arrival order, checkpoints, replay fingerprint. It resolves speakers from the catalog characters and supplies facts through a host delegate.
- The host (Godot or headless) renders: it receives keys and arguments, resolves locale text with `LocaleRenderer`, and draws portraits by id.

## 7. Thirtieth pass (2026-10-28): what changed since section 6

Section 6 is the first build. Where it conflicts with this section, this section is current.

- **D2** is now fully met: `GraphGenerator` and `GeneratedGraphTests` (250 valid seeds, 14 single defects each, 500 text-damaged documents) assert the loader's refusal code and no crash.
- **D4** is now met for fractions and ordinals: the CLDR plural table is embedded (`cldr-plurals.json`) and interpreted; every CLDR sample is tested for 10 locales, cardinal and ordinal (he added); decimals are read as text; select/gender forms; isolates for ar/he. Section 6's "plural rules written from memory, whole numbers only" no longer holds.
- **Features adopted** (Ink, Yarn, Fluent, Articy): subflows with return, interruption, timed choices, sequence/cycle/once/shuffle variants (seeded, in the save), tags, voice/emotion ids, auto-advance, visit counts, document and save format 2 (format 1 is refused with `DLG_SAVE_FORMAT`/`DLG_FORMAT`), locale fallback chains with a remembered missing-key report, translator sheets (export/import with coverage and a stale-sheet flag), `DialogueEngine.Cli` (`check`, `explain`, `export-strings`, `import-strings`, `coverage`, `graph`).
- **Trace/explain**: `ExplainChoice` and `LastTrace` are deterministic, bounded (512 entries x 512 characters) and change nothing a call does.
- **Save/load**: round trips after every call of a session through subflow, interruption, timeout and variant; forged frames are refused as a state before the digest is read.
- **Hot reload**: `ReloadMode.Refuse` (default) or `RestartConversation`; the report names the closed conversation.
- **D5b cheat-free** (`CheatFreeTests`): a condition reads only `var.*`, `visits.*` and `quest.*` from the session state and only declared `ext.*` facts from the host; the host's attempt to supply a `var.`, `quest.` or `visits.` fact, or an undeclared one, changes nothing and is never asked for; a condition on an undeclared fact is refused at load; a source guard that the core reads no clock, random source, environment or game type.
- **ScenarioEngine integration** (`DialogueMissionIntegrationTests`): the mission owns the objective; the dialogue reads its status as a host fact in its own Update; a quest request raised before the dialogue's Update is answered in the same tick the objective completes, one raised after it is answered in the next Update with the facts of that moment; refusals are events and change nothing; the dialogue state and save hold no objective status; a source guard that neither dialogue project names an objective or the mission.
- **D10b scale** (`ScaleTests`). The document limits are 256 conversations of 512 nodes each (131,072 nodes). Measured here (Release, tiered compilation off, 5 repeats, same machine and process): load of 511 nodes 9 ms; 2,555 nodes 40 to 57 ms; 5,110 nodes 104 to 155 ms; **10,220 nodes (1.4 MB) 216 to 249 ms**; 51,100 nodes 1.2 s; 130,816 nodes (18 MB) 3.0 to 3.7 s (a little worse than linear, 5x the nodes costing 4.7x the time). In a 10,220-node document, 100,000 calls take 103 to 160 ms (the first repeat is slowest), 1,000,000 calls 1.06 to 1.41 s, about 1.1 microseconds a call, the same as in a 201-node document. After five million calls the save is 16,474 bytes (15,454 after the first 100,000 calls); it grows only with the digits of the visit counts. Writing and opening a save take under 1 ms once warm (the first write measured 86 ms and the first open 23 ms, JIT). The tests bound this loosely (load under 10 s, allocation per step equal in a 255-node and a 10,000-node document within 1 percent, save growth no more than 2 bytes per visited node over 195,000 answers).

### 8.2 Hot reload that follows renames (`ReloadMap`)

`Reload(next, mode, map)` takes an optional strict JSON map (`format` 1; tables `conversations`, `nodes` as `conversation/node` to `conversation/node`, `variables`, `quests`, `stages` as `quest/stage` to the new stage id). The variables, quests, quest stages, open conversation, the calls it is inside and every visit count move to their new names, so the count `visits.*` conditions read and the variant position follow the node. The map is checked against both documents first: `DLG_MAP_FORMAT` (not a map, unknown field, duplicate key, bad id, over the size), `DLG_MAP_UNKNOWN_SOURCE` (the old document has no such name), `DLG_MAP_UNKNOWN_TARGET`, `DLG_MAP_CONFLICT` (two old things would become one). A reload that is refused changes nothing; without a map a renamed variable or quest is `DLG_RELOAD_INCOMPATIBLE` as before. `ReloadReport.RenamedVisits` counts the moved counts. The component carries the map in `DialogueReloadRequested.Map`; `DialogueEngine.Cli reload-map old new map` checks a map without a session. Not done: splitting or merging nodes or variables, changing a variable's type, mapping one old name to two new ones.

### 8.3 Import from Yarn Spinner and Ink

`YarnImporter` and `InkImporter` (in `DialogueEngine.Core/Import`) turn a Yarn Spinner 2 script or a compiled Ink story into a dialogue document and a source-locale strings table, through one `ImportBuilder` that owns the document shape, drops what nothing leads to, and has the loader and the locale coverage check accept the result (`DLG_IMPORT_INVALID` otherwise). Refusals: `DLG_IMPORT_SYNTAX` (not Yarn or not Ink, an undeclared variable, a jump to nowhere), `DLG_IMPORT_UNSUPPORTED` (valid source this engine cannot say; the line or construct is named). The Cli command is `import yarn|ink <source> --id --locale --out --strings [--start]` and `import matrix yarn|ink`. Every row of both capability matrices carries a sample source and is run by `ImportTests`, so the table cannot drift from the code.

Sources read on 2026-10-28: Yarn Spinner documentation (docs.yarnspinner.dev: nodes and lines, logic and variables, the full documentation text for options, jump, if/elseif/else, comments; the pages for detour, tags and shadow lines were not reached, which is why detour is refused and tags are limited to the `#word` form on a line's end) and the Ink runtime JSON format (github.com/inkle/ink, Documentation/ink_JSON_runtime_format.md: containers, text and newline, diverts, control commands, choice point flags 0x1 to 0x10, named content, variables).

**Yarn Spinner:** converted: nodes, lines with a speaker, `->` options with bodies, `<<jump>>`, `<<stop>>`, `<<declare>>` (whole number, true/false, text), `<<set>>` (literal, `+=`, `-=`, `$x = $x +/- n`), `<<if>>/<<elseif>>/<<else>>`, conditions (and, or, not, six comparisons and their words, a variable against a value on either side), `{$variable}` in a line, `#tags`. Approximated: a line without a speaker (spoken by `narrator`), an option's `<<if>>` (hidden when false; with none left the conversation continues after the group), a command with no arguments (a signal), `[markup]` (kept in the text). Dropped: `#line:` ids, headers other than `title`, nodes no jump from the start reaches (choose another `--start` to convert them), statements after a `jump`/`stop`. Refused: `<<detour>>`, `<<once>>`, `<<enum>>`, `<<call>>`, `<<wait>>`, `<<return>>`, commands with arguments, decimals, function calls in conditions, arithmetic between variables, expressions in `{ }`, variables in an option's text, `<<jump {$x}>>`, comparing two variables, a command inside a line.

**Ink (compiled JSON, inkVersion 19 to 21):** converted: text and newlines, tags (`#`, `/#`), diverts to knots, stitches, gathers and choice branches, `done`/`end`, sticky choices, choices with start content and choice-only content (the branch echoes the start content). Approximated: once-only choices (a true/false variable of the document, set when taken, hides the answer; every answer spent ends the conversation). Dropped: tags that are not ids. Refused: glue, variables, any expression or read of a variable, conditional diverts and choices, fallback choices, functions, tunnels, threads, sequences/cycles/shuffles (they compile to visit counts and expressions), lists, external functions. **Limit stated plainly:** `inklecate` is not installed here, so the Ink converter was tested on JSON written to the published format, not on compiler output; a real story may use a construct in a shape the tests did not see, and it is then refused, not guessed.

### 8.4 Small accessibility data

Already in the format: `autoAdvanceMs` on a line (a host that advances by itself waits that long; Ren'Py's auto-forward time is a host preference of the same kind), `tags` on lines and answers (a convention such as `cw.violence` for a content warning is ordinary tag use; the engine gives it no meaning). New: `LineStep.Seen` / `DialogueLineShown.Seen`, true when the line was shown before (the node was entered earlier, or it is the waiting line shown again after an interruption): enough for a host to offer Ren'Py's "skip only text that has been read" (the `skip_unseen` preference, https://www.renpy.org/doc/html/preferences.html, read 2026-10-28); it derives from the visit counts, so a save and a reload keep it. The Game Accessibility Guidelines list player-paced text among their basic recommendations (https://gameaccessibilityguidelines.com/basic/, seen in a search result only; the guideline page itself was not readable). A history or backlog is a host view over the `DialogueLineShown` events it has seen (keys and arguments, no text); the engine keeps none, so nothing in a save grows with reading.

### 8.5 Random walks (property tests)

`FuzzTests` (DialogueEngine.Tests): 400 seeds of generated valid documents of 8 to 60 nodes, 300 calls each with random answers, calls the session must refuse (wrong kind of call, unknown answer, timeout without a timer, interruption), random saves (every one must open to the same state and write the same bytes) and reloads of the document onto itself; each seed must end in the same state, transcript and save bytes as the same calls played straight without saves, and hash the same when played twice. A second test resumes from a save taken every fifth call of 12 long walks. `DialogueHardeningComponentTests`: 60 seeds through the real component with random requests, pauses of up to 25 ticks in one Update, journal replay verified tick for tick, the same script hashing the same on every tick, and a checkpoint at a random frame resumed in a new session that shows the same events to the end and ends in the same state and save bytes. The generator makes one conversation of lines, choices, branches, random nodes and effects; it does not generate calls, variants, quests or external facts, so those are covered by the earlier targeted tests and not by the random walks.

### 8.7 Tests and mutation checks

### 9.2 A request nobody serves is refused (`DialogueChannels`)

`DialogueChannels` is a component a game adds once and gives to every `DialogueComponent`. Each component serves its channel from Init (`DLG_CHANNEL_DUPLICATE`, refused at Init, when two serve one); the registry connects to the same ten request events through one shared `DialogueRequestPort` (so the list of requests cannot disagree between the component and the registry) and answers a request on an unserved channel in its next Update with `DialogueRefused` code `DLG_CHANNEL_UNKNOWN`, on that channel, in arrival order. ### 9.3 Priority between conversations

A conversation may say `"priority"` (0 to 1000, default 0), `"onBusy"` (`refuse`, the default, `queue` or `preempt`) and `"interruptible"` (default true). Starting a conversation while another is open follows the **starting** conversation's rule:
- `refuse`: `DLG_BUSY` as before.
- `queue`: the start waits in a queue of at most 8 (`DLG_QUEUE_FULL`; the same conversation twice is `DLG_ALREADY_QUEUED`); when everything open has finished, the highest priority starts, first come first served among equals, in the same call that ended the last conversation. The step is `StepKind.Queued` and a `queued` event says the place.
- `preempt`: allowed only when the priority is strictly higher than the open conversation's (`DLG_PRIORITY`; priority 0 cannot preempt, refused at load) and that conversation allows it (`DLG_NOT_INTERRUPTIBLE`). The open conversation's waiting line or choice is pushed as a frame marked `Preempted`; when the preempter ends (an `end`, or a `return` from its top), the stack is cut down to that frame, calls and interruptions inside the preempter are dropped, and the conversation is put back exactly where it was (shown again, not a new visit, not recorded again). Levels stack (to the call depth limit of 8, `DLG_CALL_DEPTH`).
The priority of a level is that of its root conversation (the one started or the one that preempted), not of a callee inside it. Events: `ConversationEvent` (`ended`, `started`, `preempted`, `resumed`, `queued`) and the component's `DialogueConversationChanged`; `DialogueEnded` now names the conversation that ended last. The host's own `Interrupt` is unchanged (no priority check). Saves carry the queue and the frames' preempt flag; `StateRules` checks that every preempter outranks the one under it, that a broken-into conversation allows it, and that the queue holds only queueing conversations, without repeats, within the limit, and only while a conversation is open; a hot reload follows renames of queued conversations and, when it closes the open conversation, drops the queue and says how many (`ReloadReport.DroppedQueued`). The silent-node budget of 64 starts again after a resume or a queue start, so the loader's per-segment check of runs still guarantees that a loaded document never fails with `DLG_STEP_LIMIT`; a trace keeps the newest 65 entries of a call that crosses segments.

### 9.4 Kept history and skipping what was read

The document says `"historyLimit"` (0 to 1000, default 100). The runtime keeps, newest last, one entry for each line shown (speaker, key, the values it showed, the tick) and each answer the player took (the choice, the answer id, the key of its text): not a seeded pick the player never saw, not a line shown again after an interruption. An entry also says whether the line had been seen, was passed by the skip rule, or shows a content-warning alternative. `Turn` numbers never repeat, so a gap shows what was pushed out. The **tick** is a number the host writes into `DialogueRuntime.Tick` before a call (the component writes its Update's tick); the engine never reads a clock. A session resumed from a save must go on from the saved tick (`RuntimeClock` takes a start tick), because history entries carry it; two tests that resumed from tick 0 failed for exactly that reason and were corrected. `History(count, newOnly)` is the query, and the component answers a `DialogueHistoryRequested` with `DialogueHistoryEntryListed` events (oldest first) and `DialogueHistoryListed`. The history is a ring (`HistoryLog`), so pushing the oldest out costs the same whatever the limit. `SkipSeen` passes the line showing and every following line already seen, up to 256, and stops at a choice, a line not seen, or the end (`DialogueSkipRequested`, `DialogueSkipped`); skipped lines stay in the history marked skipped. A save checks every history entry against the node it names (kind, speaker, key or alternative, placeholder names, answer id); a reload keeps an entry only if its node still matches, follows renames, and trims to the new limit, reporting `DroppedHistory`.

### 9.5 Content warnings

A document declares `"contentWarnings"`: for each, a tag (`cw.` and a name), the id of a declared **true/false external fact** (true: this player has blocked it) and an action, `skip` or `replace`. A line or an answer carrying the tag is checked against the fact when it is reached: a blocked `skip` line is passed without being shown (and without counting as seen; the visit is taken back; it is not in the history) and a blocked `skip` answer is hidden; a blocked `replace` line or answer is shown with its declared `"alternative"` key (`Replaced` on the event; the same placeholders as the original). If a line carries two warnings and one skips, skip wins. Loader refusals: `DLG_CW_UNDECLARED` (any tag starting `cw.` that is not declared, or a declaration whose tag is not `cw.` and a name), `DLG_CW_FACT` (the fact is not a declared true/false external), `DLG_CW_ALTERNATIVE` (a replacing warning without an alternative, or an alternative with nothing to replace); a missing policy fact at play time is the usual `DLG_FACT_MISSING`. A line that can be skipped does not count as a wait for the loop and silent-chain checks. The explain call names the warning that hides an answer. **Tags stay free tags for everything else.**

### 9.6 Signals with arguments, and glue

`{"signal": "name", "args": [{"text": ..}, {"int": ..}, {"bool": ..}, {"var": "id"}]}` (1 to 8 arguments; a `var` is read when the signal is raised) and `"glue": true` on a line (`LineStep.Glue`, the event's `Glue`): the host joins the line to the next. ### 10.1 The channel registry cannot be forgotten

Choice: **the request port requires the registry, and the registry is the only way to declare the dialogue events.** `DialogueChannels.Install(session)` (an instance method now: `new DialogueChannels().Install(session)`) declares the events (`DialogueEventCatalog` is internal) and adds the registry as the session's last component (`Order = int.MaxValue`); `DialogueComponent` takes the registry as a required constructor argument (`null` is refused). So a dialogue request cannot be raised in a session whose registry is missing (the event is not declared), a component cannot be built without one, and a registry that was built but never installed fails at the component's Init ("event is not declared"). A component whose registry runs on another session (or whose session was not initialised) fails its **first Update** (fail-stop, reported through the session's reporter), and a registry cannot serve two sessions (its Init refuses).
Why not "detect unanswered requests at the end of Update": that would be a second global rule about which request has an owner, beside the registry that already knows the served channels. The registry updates last, so a refusal now comes in **the same tick** as the request, whichever component raised it (pass 32: the next tick for a request raised by a late component, and only if the game had added the registry). In a tick the refusal event now follows the answers of the real components (tests updated: `TwoConversationsRunSideBySide...`, `AResumedSessionRefuses...`). ### 10.2 Yarn Spinner: random functions, and visit counts shared by every start

Source read 2026-10-28 (docs.yarnspinner.dev, Functions): `random()` "a random number between 0 and 1"; `random_range(a, b)` "between a and b, inclusive"; `dice(sides)` "an integer between 1 and sides, inclusive"; `visited(node)` / `visited_count(node)` look the node up by title in the project (the page does not say in so many words that counts are program-wide; the title lookup implies it). All three random functions are the document's **seeded, checkpointed roll** (a `random` node: the same seed and roll count give the same value; the roll counter is in the save), never a host fact.
- `<<set $x to dice(n)>>` and `random_range(a, b)` with whole-number arguments: up to 16 values in one random node; up to **100 values** in two stages (a bucket by its size, then a value in it, so every value stays equally likely). One node per value sets it, so a conversation (512 nodes) holds about four d100 assignments. More is refused (`DLG_IMPORT_UNSUPPORTED`).
- In conditions: `dice(6) >= 5`, `random_range(1, 10) < 4`, `4 < dice(6)` and `random() < 0.25` (the roll on either side). The comparison is decided by one roll made before the statement that holds the condition, into a hidden true/false variable (`roll-N`) that is true with exactly the probability the comparison has (counted in closed form for ranges, kept to the thousandth for `random()` and for fractions the weights of a random node cannot hold). Approximated and reported so: every roll of an `if`/`elseif` chain is made before the first branch is tested (Yarn tests them one at a time), and an option's condition is rolled before its choice.
- Refused (`DLG_IMPORT_UNSUPPORTED` or `DLG_IMPORT_SYNTAX`): `random()` stored in a variable (variables are whole numbers), `random()` with `==` / `!=`, a roll against a variable or another roll, a roll shown in text, `random_range(5, 1)`, `dice(0)`, non-whole arguments.

### 10.3 Ink

- **Glue at the start of content reached by a divert**: the divert's run must have said a line immediately before it (variable changes between are allowed); that line gets the glue flag and the target is made without its glue. A divert that is the first thing in its run, glue after a conditional divert, a choice or a tunnel, and glue at the start of a choice branch are still refused, with a message that says which.
