Purpose and status

The intended purpose was a reusable, engine-independent grid space for games that need deterministic geometry: cells and millimetre points, integer-only distance, terrain costs, field of view, paths and line of sight, with a checksummed state.

Only the numeric core was written. It is useful as a reference for exact integer distance and coordinate conventions; it is not a spatial engine.

The sketch

TypeWhat it does
Cell(int X, int Y)A grid cell counted from the top-left corner.
Point(long X, long Y)A point in whole millimetres. There is no floating point.
TerrainDef(int Index, string Id, int Cost, bool BlocksSight, char Symbol)One terrain row: movement cost, sight blocking, map symbol.
MetricCoordinateLimit (10¹²), Distance(dx, dy) and Distance(Point, Point) — exact floor of the Euclidean distance using integer square root, so every machine agrees to the last millimetre.
SpatialCodesThe intended refusal and query codes: SPT_FORMAT, SPT_*, plus Found, Blocked, Unreachable, Budget and the save codes.
 
var a = new Point(0, 0);
var b = new Point(3_000, 4_000);
long mm = Metric.Distance(a, b);   // 5000, exact integer arithmetic

The codes describe a map document, calls, query outcomes and a checkpoint that the sketch does not yet implement. Treat them as reserved names, not as a contract in use.

Boundary with Godot and SimEngine

  • Simulation truth belongs to SimEngine. Its MapLayer/TileMap, NavGrid/PathSearch, Mover, regions and spatial-resource contracts already own deterministic paths, distances, line of sight, fog and hashed state.
  • Presentation belongs to Godot. Rendering, camera, animation and input use Godot's native features; a game does not reimplement them.
  • Do not build a third spatial authority. If a game needs geometry that enters the simulation hash or replay, extend SimEngine's existing spatial contracts. If it is only visual, use Godot.

What the design record covers

docs/SPATIAL_ENGINE.md records the research, the Godot boundary rule, the layer decision, the proposed map format 1, acceptance criteria and the parked result. It is a design document, not evidence of a working implementation.

If this work resumes

  1. Decide explicitly whether the capability belongs in SimEngine's spatial layer (likely) or in a genuinely separate kernel; record the decision in the design record.
  2. If separate: add the project to the solution, write the map reader and validator with coded refusals, then the queries, checkpoint and tests — in that order.
  3. Do not claim completion from the sketch. The current acceptance status is not run.
