Purpose

AlchemyEngine answers one question: what happens when these items are combined in this environment? It owns the rules and the player's knowledge, not the inventory, the workshop or the presentation. It has no clock, no counters and no random state — the caller passes a seed, an attempt number and environment tags.

It owns

Content validation, recipe matching, exact-fraction chance, the discovery book (elements, recipes, tried combinations, attempts), save and hash.

It does not own

Inventory quantities, UI, unlocks, rewards, crafting time, or what a discovered element is worth. Those are game-layer decisions.

Refuse, never repair

Bad content or a bad request raises a coded exception. Nothing is defaulted, skipped or guessed.

Content format

Strict JSON with a version number. The loader refuses unknown or missing fields (ALCHEMY_UNKNOWN_FIELD, ALCHEMY_MISSING_FIELD).

{ "format": 1,
  "elements": [
    { "id": "water", "name": "Water", "properties": ["liquid"], "starting": true },
    { "id": "steam", "name": "Steam", "properties": ["gas"], "starting": false } ],
  "recipes": [
    { "id": "boil-water",
      "inputs": ["water"], "catalysts": [], "environment": ["heat"], "outputs": ["steam"],
      "ordered": false, "chance": { "numerator": 1, "denominator": 4 } } ] }
FieldMeaning
id, name, properties, startingElement identity and the tags the game may query. At least one element must be starting.
inputsConsumed by the reaction. Non-empty.
catalystsMust be present but are not consumed; returned in Kept.
environmentTags (for example heat) that must all be offered by the caller.
outputsWhat appears. Non-empty.
orderedWhen true, inputs must arrive in exactly the declared sequence; otherwise any order matches.
chanceExact fraction numerator / denominator, denominator at most 1,000,000. 1/1 always reacts.

Validation also refuses duplicate ids, a catalyst that is also an input, bad chances, no starting element, an ambiguous pair of recipes that could both match one combination, and an element that no chain can ever produce (ALCHEMY_UNREACHABLE_ELEMENT).

Matching rules

  • At most AlchemyRules.MaxItems = 8 items; empty is refused; every item must exist in the content.
  • Environment tags are deduplicated and sorted; each must be 1–64 chars of a-z 0-9 . _ -.
  • Recipes are grouped by the order-free vessel key (inputs + catalysts, sorted). A recipe fits when all its environment tags are offered and, if ordered, its non-catalyst inputs equal the request sequence.
  • More than one fitting recipe is a content bug and is refused at combine time (ALCHEMY_COMBINE_AMBIGUOUS) — the loader normally prevents it.
  • Outcomes: Reacted, NoReaction (valid but no recipe), Fizzled (recipe fits, chance failed), Refused (bad request; Code says why).

Chance and determinism

text  = "alchemy-roll|" + seed + "|" + attempt + "|" + recipe.Id + "|"
      + string.Join('+', items) + "|" + string.Join(',', environment);
hash  = SHA256(text);
value = first 8 bytes big-endian;
reacts when value % denominator < numerator

Because the roll depends only on the seed, the attempt, the recipe and the canonical request, replaying a journal reproduces every reaction. A fizzle is chance, not a conclusion: the book does not record it as tried, so the next attempt rolls differently.

The discovery book

DiscoveryBook is the player's knowledge: known elements, known recipes, tried combinations and a monotonic attempt counter used as the chance input.

  • A new book knows exactly the content's starting elements.
  • CheckUsable(items) returns ALCHEMY_COMBINE_NOT_DISCOVERED when an item is unknown — a player cannot combine what it has not found.
  • Record(result) teaches nothing for a refusal; a fizzle costs an attempt but stays untried; a reaction adds outputs and the recipe.
  • LearnRecipe(id) teaches from outside (scroll, teacher, research) and does not count as an attempt.
  • Hash() is SHA-256 over content digest, attempts and sorted sets — the per-tick fingerprint for a journal.
  • A saved book names the content digest; it will not load against other content (ALCHEMY_BOOK_CONTENT).

Public API

MemberContract
AlchemyContentLoader.Load(json)Validate and build immutable content; throws AlchemyContentException/AlchemyRefusedException with a code.
AlchemyRules.Combine(items, new CombineContext(seed, attempt, environment))Match, then roll the exact chance. Pure.
WhatDoes(items, environment)The match without rolling: useful for a hint or a preview.
WhatMakes(elementId)Every recipe producing the element, ordered by id.
new DiscoveryBook(content)Starting knowledge; then Record, LearnRecipe, CheckUsable, HasTried.
book.Save() / DiscoveryBook.Load(content, bytes)Envelope with content digest and body digest; loading refuses a different content or a tampered body.

GameRuntime integration

AlchemyComponent(rules, book, seed, id = "alchemy") queues CombineRequested and RecipeLearnedExternally, then answers inside Update in arrival order, using the book's attempt counter as the only variation.

EventDirection
alchemy.combine-requested, alchemy.recipe-learned-externallyRequest in
alchemy.combined, alchemy.combine-refused, alchemy.discovery-madeResult out
alchemy.knowledge-restoredEmitted at Init so a host can rebuild its view

IsQuiet is true only when no request or external lesson waits; Fingerprint() reports tick, book hash and pending count. Declare AlchemyEventCatalog before Init.

SimEngine bridge

GameRuntime.AlchemySim turns alchemy discoveries into production: SimRecipeSource.Alchemy projects recipes into SimEngine content, RecipeUnlockComponent opens a recipe when its discovery event arrives, SimProcessor runs the production step, and DiscoverRecipeEffect turns a produced item into a book discovery. The proof game is the alchemist workshop under src/GameRuntime/GameRuntime.AlchemySim.Headless/Workshop.
