ScenarioEngine

A standalone scenario kernel: validated JSON content, typed facts and conditions, objective graphs with endings, replaceable game layers, transactional command admission, world frames, checksummed saves, previous-generation recovery and portable recorded replay — with no engine or Godot dependency.

Purpose

ScenarioEngine is the mission and objective framework for games that need a win/lose structure: objectives that lock, activate, complete or fail, typed facts, exhaustive endings, and a repeatable tick loop over an authored scenario. The kernel contains no domain rules and no renderer; a game supplies a game layer that implements the mission's own verbs.

It owns

Content validation, conditions, objective graph, endings, command admission, tick transaction, snapshots, save/recovery, replay, diagnostics.

The game layer owns

Domain state and rules, operations, effects, observations and projected facts. It is pure: previous snapshot in, candidate state and events out.

Transactional

A failed tick rolls back. Commands are bounded, owned by a controller, deduplicated and fingerprinted before they are admitted.

Content and validation

  • A pack is a normalized JSON document up to 1 MiB, read through IScenarioPackSource (JsonFilePackSource for the headless host).
  • IScenarioContentService.LoadAsync validates with IContractValidator before anything is registered; cancellation is honoured before registration.
  • Semantic checks add identity, digest, zone/exit/objective reference checks and ending-coverage rules on top of the schema.
  • RemoveFromCatalog removes a pack/digest from new selection; existing sessions keep their immutable definitions.
  • A validated scenario is a ValidatedScenario(ScenarioIdentity, ScenarioDefinition); the identity carries pack id/version, content digest, scenario id and layer id/version.

Contracts: facts, conditions, objectives, endings

public abstract record Condition;
public sealed record AllCondition(ImmutableArray<Condition> Children) : Condition;
public sealed record AnyCondition(ImmutableArray<Condition> Children) : Condition;
public sealed record NotCondition(Condition Child) : Condition;
public sealed record CompareCondition(string Fact, string Operation, FactValue Value) : Condition;
  • Facts are boolean, integer or text; a layer declares each fact and its bounds.
  • Objectives have dependencies (with accepted statuses), activate/complete/fail conditions and success/failure effects.
  • Endings have a priority, a condition and outcome tags. Ambiguous or unreachable endings are refused at validation.
  • Zones and exits name anchors, target zones, conditions and durations; every target must exist.

Game layers

public interface IGameLayer
{
    string Id { get; }
    string Version { get; }
    LayerCapabilities Capabilities { get; }
    ValidationReport Validate(JsonElement content);
    ILayerRuntime Create(LayerStartContext context);
}

public interface ILayerRuntime
{
    LayerSnapshot InitialState { get; }
    LayerStepResult Resolve(LayerSnapshot previous, LayerTickContext context);
    LayerEffectResult ApplyEffects(LayerSnapshot candidate, ImmutableArray<EffectEnvelope> effects, LayerTickContext context);
    ImmutableDictionary<string, FactValue> ProjectFacts(LayerSnapshot state);
    ValidationReport ValidateState(LayerSnapshot state);
}
  • A layer declares its operations, effects, observations, facts and content schema, so commands and observations are checked before they reach it.
  • LayerTickContext supplies the tick, fixed step, world frame, admitted commands and seeded random streams; a layer never reads a clock.
  • Resolve returns the next snapshot, per-command outcomes, domain events and world requests. ApplyEffects handles ordered effects.
  • A layer that can prove an idle tick does nothing may implement IIdleTickRuntime.
  • Register layers in GameLayerRegistry at the composition root. Registration accepts implementations; it does not scan or execute DLLs named by JSON.

Simulation and commands

using var session = factory.Create(validated, startOptions, initialWorld);
AdmissionResult admitted = session.Enqueue(new CommandEnvelope(
    commandId, controllerId, targetTick, worldGeneration, operation, payloadJson));
AdmissionResult cancelled = session.CancelQueued(controllerId, commandId);
StepResult step = session.Update(new TickInput(tick, worldFrame));
  • Commands are bounded (payload ≤ 64 KiB UTF-8, depth 32, duplicate JSON properties refused), owned by a controller and fingerprinted; a duplicate id is not admitted twice.
  • A world frame carries at most 256 observations within a 1 MiB aggregate budget; an invalid frame yields an uncommitted result and the session keeps running.
  • Update advances one integer simulation tick. StepResult reports committed, a code, the tick, events, world requests, the snapshot and the rule-state hash. A failed tick is rolled back.
  • ScenarioEngine.StateHash(snapshot) gives the stable state digest used by saves and replay.

Session snapshot and restore

SessionSnapshot is the complete session: identity, session id, seed, controllers, phase, tick, world generation, sequence counters, objectives, applied effects, ending/outcome, layer snapshot, pending commands, receipts and random-stream states.

  • SessionSnapshotRules validates queued commands, payloads, controllers, fingerprints, duplicate sequences, receipt relationships and phase values before a snapshot is accepted.
  • ScenarioSessionFactory.Restore(scenario, snapshot, restoredWorld) rebuilds a session; the scenario and layer are revalidated first.
  • Controller matching is ordinal regardless of the caller's comparer.

Save, recovery and audit

  • SaveDocument carries save format, engine build id, UTC time and the snapshot; the save codec produces bytes with integrity checksums.
  • ISaveStore is the replaceable storage boundary; LocalFileSaveStore implements real file replacement.
  • IRecoverableSaveStore (optional) exposes an earlier generation. IScenarioSaveRecoveryService.LoadPreviousAsync validates and audits it before returning; missing, corrupt or unreadable backups have explicit diagnostics.
  • Load reads the current generation only; recovery reads the backup only after the host selects it. Neither promotes, repairs or rewrites files.
  • An audit failure leaves the catalog unchanged. Checksums detect modification; they are not authentication.

Replay

var service = new ReplayService(sessionFactory, reporter);
IReplayService replay = service;
IReplayCodec codec = service;
using var recorded = replay.Record(session, initialWorld);
recorded.Enqueue(command);
recorded.Step(tickInput);
byte[] bytes = codec.Encode(recorded.CaptureReplay());
ReplayResult result = replay.Verify(scenario, codec.Decode(bytes).Tape!);
  • The tape holds the starting snapshot/world, commands, cancellations, start/pause/resume/step/dispose calls and expected hashes for state and returned events/requests/receipts.
  • Verification identifies the first divergent entry and checks initial content identity and SHA-256 integrity.
  • Tapes are bounded to 10,000 entries / 16 MiB. The recorder owns its session; use it exclusively while recording.
  • Replay records explicit world inputs; synthetic-input checks do not prove native navigation.

Diagnostics and notifications

IEngineReporter / ApplicationDiagnostics record operations and failures; EngineNotice and INotificationSink (ConsoleNotificationSink in the host) surface them. AuditRecord names the operation, target, result and session. Validation findings are Diagnostic(Code, Message, File, Pointer, Severity).

Hosting and the simulator

dotnet build ScenarioEngine.slnx -c Release
dotnet run --project tools/ScenarioSimulator/ScenarioSimulator.csproj -c Release
dotnet run --project tests/ScenarioEngine.Tests/ScenarioEngine.Tests.csproj -c Release -- -noColor

ScenarioSimulator is the headless composition root: it loads JSON, initializes, submits an order per tick, updates, reaches an ending, writes two save generations, restores the previous one and compares continuation and replay hashes. The Counter sample is the minimal working layer.

For GameFrameWork, src/GameRuntime/GameRuntime.Scenario/MissionComponent adapts the mission to the runtime's event model, and GameRuntime.Services uses IScenarioSaveCodec for composite checkpoints.

Testing

The suite covers engine behaviour, content validation, objectives and endings, persistence and recovery, replay budget/verification, plugin registration, boundary passes and source-and-factory checks. tools/Verify-ScenarioEngine.ps1 runs scoped checks and records commands and results under artifacts/verification.
