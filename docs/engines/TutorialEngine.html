Purpose

TutorialEngine decides what a new player is taught and when. It never draws a highlight or plays a sound; it emits views (step, hint, tip, journey page) with localisation keys and a motion hint, and the host presents them. Completion is driven by observed facts and events — the player actually built the thing — not by the player clicking "next".

It owns

Journey, steps and dependencies, event counting, skills/mastery, hint escalation, tip eligibility and priority, skip/replay/resume, accessibility flags and the save.

It does not own

Rendering, highlight implementation, audio, input mapping into game actions, or the text itself.

Deterministic

Time is the step counter. Progress depends only on state, events and host facts; a save is a complete copy of that state.

               "requires": [], "requiresAny": [],

               "hints": [ { "idle": 300, "kind": "nudge", "key": "tut.hint.shelter.nudge" } ] } ],
  "tips": [ { "id": "journal-tip", "key": "tut.tip.journal",
              "when": { "fact": "step.shelter.status", "op": "eq", "value": "Active" },
              "cooldown": 5, "maxShows": 1, "duration": 10, "priority": 50,
              "skill": "building", "afterStep": "shelter", "motion": "slide" } ] }

Strict JSON: unknown or missing fields, duplicate ids, dangling references, invalid conditions, unreachable steps and over-large bounds are refused with TUT_* codes. Every player-visible string is a localisation key.

Steps and completion

  • A step is available when every requires entry is satisfied and, if given, one requiresAny entry was really done (bypassed alternatives only let the step continue when all alternatives were bypassed).
  • When when is false the step is bypassed (a branch not taken); when its skill is mastered it is mastered; otherwise it becomes active until complete holds.
  • Completion reads facts; an event's event.<id>.since_step fact counts only what happened since the step began. A step may be skippable.
  • Statuses: Pending, Active, Done, Skipped, Mastered, Bypassed. ProgressPermille and Satisfied summarise progress.
  • maxActiveSteps usually 1, so the player has one main task at a time.

Hints

After idle steps without activity a step's hint appears, escalating from Nudge to Explain to Show. A hint is a HintView(Step, Level, Kind, Key, Target, Motion); the host decides how to present it. Activity (Touch/Resume) resets the idle count.

Tips

  • A tip shows while when holds, at most maxShows times, at least cooldown steps apart, for duration steps, and only after afterStep when given.
  • Priority breaks competition when more tips are eligible than maxVisibleTips; tipGap keeps two tips at least that many steps apart.
  • A tip ends as Shown, Dismissed, Expired or Withdrawn.

Skills and mastery

A skill collects evidence from events; at mastered points the player is taken to know it, so its steps are mastered and its tips are not shown. This is how a returning player skips what they already know without a separate "experienced" flag.

First-run journey

JourneyState: Language → Story → Entry → Done. The journey has languages, story pages (title, body, art keys) and entries (guest, sign-in, register, join). SelectLanguage, StoryNext/StoryBack, StorySkip, ChooseEntry, and ReplayStory drive it. Story replay is separate from tutorial replay.

Accessibility

SetReducedMotion(bool) turns every Pulse/Slide into None. SetTextScale(permille) records the player's text size. SetTipsEnabled(bool) suppresses tips without losing progress. These are state, saved with the session, so a host applies them consistently.

Runtime API

var set     = TutorialLoader.Load(json);
var runtime = TutorialRuntime.Create(set, startStep: 0);
runtime.Start();
runtime.Observe("built.shelter");                 // an event happened
TutorialChanges c = runtime.Advance(step, hostFacts);   // time passes; evaluate steps/hints/tips
runtime.SkipStep("shelter");
runtime.SkipTutorial();
var hints   = runtime.Hints();
var tips    = runtime.VisibleTips();
var step    = runtime.StepState("shelter");
var digest  = runtime.StateDigest();

TutorialChanges lists typed changes (step, skill, hint, tip, journey) for the game layer. Advance is monotonic; Evaluate re-evaluates without advancing.

Facts

TutorialFacts declares the facts conditions can read: event.<event>.count, .ago, .since_step; step.<step>.status, .done; tip.<tip>.shows, .acknowledged, .visible; skill.<skill>.points, .mastered; tutorial.phase, tutorial.progress; journey.state, journey.language; and setting.reduced_motion, setting.text_scale, setting.tips. Any other id is the host's. since_step is only meaningful in a step's completion condition. ReadFacts(prefix) exports them for dialogue or AI.

Save and replay

TutorialSave writes the session image; StateDigest() is the canonical digest. A save names the document digest and refuses a mismatch (TUT_SAVE_DOCUMENT) or a tampered state (TUT_SAVE_STATE). Replay() restarts the tutorial from the beginning while keeping the journey and settings where the design says so; ResetTips() clears tip history.

Exit codes: 0 done, 1 refused or incomplete, 2 usage/scenario/file problem.

GameRuntime integration

TutorialComponent applies observed events, host facts, controls and player choices inside Update, and publishes step/hint/tip changes.

Request inResult out
start, observe, advance/evaluate, skip step, skip tutorial, replay, language, story, entry, reduced motion, text scale, tips enabled, dismiss tiptutorial.step-changed, hint-shown, tip-shown/tip-ended, skill-changed, journey-changed, refused

TutorialBridges maps game events into observations (build completed, menu opened). The input component maps authored actions to events. A checkpoint is consistent when no request waits.
