Purpose

CalendarEngine is the single owner of in-game time. It converts a tick count into a date, time of day, weekday, season, daylight level, moon phase and holiday state — and back — using whole numbers only. It also says where each actor should be and what it should be doing at an instant, from day-part routines with interrupts.

It owns

Calendar declarations, date arithmetic, leap rules, recurrence, seasons and daylight, moons, holidays, schedules and interrupts, time advancement and its save image.

It does not own

Gameplay speed decisions, rendering, localised strings (it emits keys), NPC movement, or real-world clock time.

Deterministic by construction

No DateTime, no floating point, no wall clock, no random. The same instant always yields the same reading.

Document format

Strict format-1 JSON. Every declaration carries a stable id and a localisation key; strings the player sees are never stored in the calendar.

weekModecontinuous or restart (weeks restart each month).
weekdays, monthsOrdered ids/keys. A month has days, leapDays and optional intercalary.

facts, schedulesHost fact declarations the selectors may read; schedules of prioritised routines of minute blocks.

Date arithmetic

long day      = system.DayNumber(new CalendarDate(year, monthIndex, day)); // month is 0-based
DayInfo info  = system.DayOf(day);
Moment moment = system.MomentOf(instant);   // refuses instants outside the supported years
CalendarDate d = moment.Day.Date;
  • Supported years are −100,000 to 100,000; instants outside that range are refused (CALENDAR_INSTANT_RANGE).
  • Gregorian, Julian and invented calendars share one engine; leap rules are declarative.
  • DaylightAt(season, minuteOfDay) returns IsDay, a 0–1000 light value ramping through twilight, sunrise and sunset.
  • MoonAt(moon, instant) returns one of eight phases and a permille position using exact fractions (Int128), so there is no drift.

Recurrence and holidays

Recurrence implements the day-granular subset of RFC 5545 §3.3.10: FREQ (daily, weekly, monthly, yearly), INTERVAL, UNTIL, BYMONTH, BYMONTHDAY (negative counts from the end), BYDAY with ordinals, plus BYSEASON. COUNT and BYSETPOS are refused because they need enumeration from the start.

  • HolidaysStartingOn(day) — holidays whose rule matches this day.
  • HolidaysOn(day) — includes multi-day holidays that started earlier.
  • NextOccurrence(rule, fromDay, withinDays) / NextHoliday(index, fromDay, withinDays) — bounded search, null when none.

Schedules and selectors

A schedule holds routines ordered by priority. Each routine has a Selector and minute blocks [From, To) with a location and an activity. A selector is an AND of the fields it gives (weekdays, months, seasons, holidays, a date recurrence, a shared condition over host facts); inside a list any entry may match.

CalendarContext context = runtime.Context(hostFacts);
ScheduleAnswer answer   = runtime.WhereIs(context, "baker");
// answer = Location, Activity, Source (Routine|Interrupt), Routine, Block, Priority, From, To

An interrupt (alarm, invitation) overrides routines while it lasts. A lower-priority interrupt cannot replace a higher-priority one (CALENDAR_OUTRANKED); an equal or higher one can.

Runtime clock

CalendarRuntime.Create(set, startInstant, scaleNumerator, scaleDenominator, startTick) binds the calendar to a rational speed: calendar ticks per game tick. The fractional remainder is carried exactly, so a long run does not drift.

MemberContract
Step(gameTick)Earns elapsed calendar ticks, applies at most 400 days, keeps the rest as Backlog. Returns TimeStep or null when nothing moved.
SkipTo(instant)Jumps forward at once (sleep until morning), at most 366 days, independent of scale and pause.
SetScale(n, d) / SetPaused(bool)Speed is 1–366 days per game tick with denominator ≤ 10,000; changing scale drops the sub-tick remainder.
AddActor / RemoveActorAt most 100,000 actors; ids 1–128 chars; the schedule must exist.
Interrupt / ClearInterruptDuration 1 tick to 366 days; priority ordering is enforced.
Refresh(context, max)Actors whose answer changed since last announced, at most max, in id order; the rest wait for the next call.

TimeStep reports days crossed, whether the instant was clamped at the end of supported time, day-part change, every season change crossed, the first 64 holiday starts and how many more were omitted. Tick order is monotonic and a single Step accepts at most 50,000,000 elapsed game ticks (CALENDAR_TICK_ORDER).

The cal.* facts

CalendarFacts.Read(set, moment) returns a fact dictionary under the reserved cal. prefix, usable by schedule selectors, dialogue conditions and AI percepts:

cal.year, cal.month_number, cal.day_of_month, cal.day_of_year, cal.weekday_number, cal.hour, cal.minute, cal.minute_of_day, cal.light, cal.month, cal.weekday, cal.season, cal.daypart, cal.era, cal.holiday_id, cal.is_day, cal.is_holiday, cal.is_leap_year, and cal.moon.<id> per moon.

CalendarFacts.Definitions(system, moons) gives the type and range of each so a dialogue document can declare them as external facts.

CalendarEngine.Cli coverage <calendar.json> <locale.json> [<locale.json> ...]

Exit codes: 0 done (for coverage, every table complete), 1 refused or incomplete, 2 usage or file problem.

GameRuntime integration

CalendarComponent applies scale, pause, skip, actor, interrupt and query requests inside Update, then advances the clock and emits what changed. Install the channels with CalendarChannels.Install(session) before Init.

EventDirection
calendar.scale-requested, pause-requested, skip-requested, actor-add-requested, actor-remove-requested, interrupt-requested, interrupt-clear-requested, where-requestedRequest in
calendar.applied, calendar.refused, calendar.where-answeredAnswer out
calendar.time-advanced, day-changed, day-part-changed, season-changed, holiday-started, schedule-block-changedChange out

CalendarJournal records per-tick channel entries; CalendarTranscript and CalendarReplay verify a recorded run and its state digest; CalendarCheckpoint captures and restores the runtime. GameRuntime.Calendar.Ai feeds calendar time to AIEngine agents.
