AIEngine

Purpose

AIEngine decides what an agent wants to do next and says so as a named intent with typed arguments. It never moves a unit, spends money, deals damage or reads a clock. The host tells the agent what it may know, calls Step(tick, budget), and receives intents. The component that owns the concern — economy, combat, simulation commands — decides what an intent means.

Three properties are deliberate:

  • Deterministic — a step is a pure function of the document, the runtime state, the tick and the budget. Random choices use a seeded, stateless roll keyed by string, so replay and save/restore reproduce decisions exactly.
  • Bounded — every behaviour has a static work-unit bound computed at load; a step never spends more than its budget, and an agent that does not fit waits and goes first next step.
  • Explainable — tracing one agent records each node it ran and why, without changing the decision, the document digest or a save.

Layer boundary

AIEngine owns

The document schema, validation and refusals, the static cost bound, the agent runtime and its scheduler, percept memory and expiry, keys, intents, save images and decision traces.

The game owns

What an intent means, which agent exists, what it perceives, host-key values, and every effect. Adapters hold no thresholds and no target rule.

GameRuntime owns

Tick order, event delivery and session checkpoints. AiComponent translates request events into runtime calls and intents into events.

Document format 1

A document is strict JSON. Unknown fields are refused (AI_UNKNOWN_FIELD) rather than ignored, so a typo cannot silently change behaviour. The reader records the digest of the exact accepted text; saves are checked against it.

{ "format": 1, "id": "guard.ai",
  "keys": [
    { "id": "distance", "type": "int", "initial": 500, "min": 0, "max": 500, "source": "host" } ],
  "percepts": [
    { "id": "enemy", "memory": 40, "capacity": 8, "owned": true,
      "attrs": [ { "id": "range", "type": "int", "min": 0, "max": 500 } ] } ],
  "intents": [
    { "id": "attack", "args": [ { "id": "weight", "type": "int", "min": 0, "max": 100 } ] } ],
  "behaviors": [
    { "id": "guard", "every": 5, "root":
      { "id": "n0", "kind": "selector", "resume": false, "children": [
        { "id": "n1", "kind": "condition", "when": { "fact": "key.threat", "op": "lte", "value": 20 } },
        { "id": "n2", "kind": "act", "intent": "hold", "args": { "weight": 40 } } ] } } ] }
SectionMeaning
keysTyped values with an initial value and a range. source is host (only the host writes) or agent (a let node writes). A key's index is its position in id order.
perceptsKinds of thing an agent can be told about, each with typed attributes, an unknown/default value per attribute, memory in ticks, and optional per-owner capacity. owned percepts are keyed by kind, owner and id.
intentsNames with typed arguments. An act node emits one; nothing else may invent an intent name.
behaviorsAn id, a think interval (every ticks), and a root node. The loader computes the behaviour's maximum work cost and the persistent slot set.

Node kinds

KindBehaviour
sequenceRuns children in order; fails on the first failure; can resume a running child across thinks.
selectorRuns children until one succeeds; fails when all fail; can resume.
conditionTests the shared condition grammar over key.*, item.* and tick.
letWrites an agent-owned key (an expression evaluated to the key's range).
actEmits an intent with literal or computed arguments.
invert / succeedFlip a child's status / report success after running a child.
cooldownBlocks re-entry for a number of ticks per agent slot.
utilityWeighs options by considerations and momentum, then runs the highest scoring.
randomSeeded weighted choice among child nodes.
forEach / count / selectQuery percepts: run a child per match, count matches, or pick min / max / nth by an attribute or fact expression.
adjustChanges a percept attribute by an expression (bounded by the attribute range).

Work accounting and budget

One work unit is charged for each node run and for each percept a query looks at. The loader computes a static upper bound for every behaviour, and AiSet.MaxCost is the largest of them.

  • Step(tick, budget) refuses a budget below MaxCost (AI_BUDGET_TOO_SMALL), because otherwise some agent could never be thought.
  • Due agents are served oldest-due first. A think only starts when the remaining budget covers that agent's whole behaviour bound, so a step never overspends.
  • An agent that was due but did not fit stays due; the next step serves it first and reports it in Deferred with the longest wait.
  • Agents added on the same tick get a seeded offset below every, so they do not all think on one tick.

Runtime API

MemberContract
new AiRuntime(AiSet set, ulong seed)Bind a loaded document to a deterministic seed.
Add(id, behavior, tick) / Remove(id)Agent ids are 1–128 chars of a-z 0-9 - . _; duplicates and unknown behaviours are refused.
Perceive(agent, kind, id, owner, attrs, tick)Tell an agent about a percept. Every declared attribute is required exactly; owned kinds need an owner; capacity overflow is refused (AI_PERCEPT_CAPACITY).
Lose(agent, kind, id)Tell an agent a thing is gone; not knowing it already is not an error.
SetKey(agent, key, value) / Key(agent, key)Write or read a host-owned key; writing an agent-owned key is refused (AI_KEY_WRITE).
Known(agent, kind)What the agent knows of one kind, in id order, as PerceptInfo.
Step(tick, budget)Think due agents, oldest first, and return a StepReport: intents, thought count, spent units, deferred count, longest wait.
Due(agent), BehaviorOf(agent), Agents, LastTickRead-only inspection. Ticks may not go backwards (AI_TICK_ORDER).
Trace(agent, on) / Explain(agent)Record and read the last decision trace of one agent.
 
var set = AiLoader.Load(File.ReadAllText("guard.ai.json"));
var ai  = new AiRuntime(set, seed: 1234);
ai.Add("guard-1", "guard", tick: 0);
ai.SetKey("guard-1", "threat", FactValue.From(15));
ai.Perceive("guard-1", "enemy", "e1", owner: "site",
            attrs: new Dictionary<string, FactValue> { ["range"] = FactValue.From(90) }, tick: 0);

var report = ai.Step(tick: 10, budget: set.MaxCost);
foreach (var intent in report.Intents)
    Console.WriteLine($"{intent.Agent} -> {intent.Name}");

Determinism, save and restore

Randomness is a stateless seeded roll: the seed and a caller-supplied string label determine the value, and a per-agent roll counter advances the label. No global random state exists, so order of unrelated agents cannot change a result.

var image = AiSave.Capture(ai);            // canonical agent rows + knowledge
var bytes = AiSave.Write(image);          // format, document digest, state digest
var same  = AiSave.Restore(set, bytes, out var restored); // verifies both digests
  • AI_SAVE_DOCUMENT — the save was made against a different document digest.
  • AI_SAVE_STATE — the state digest does not match; the image was edited or corrupted.
  • A checkpoint is only consistent when the runtime has no pending request waiting to be applied.

Explaining a decision

Trace(agent, true) records every node run, its depth, kind, status and detail for that agent's next think; Explain returns a ThinkTrace with the tick, units spent and whether recording was truncated. Recording is observation only: it does not change a choice, the set digest or a save. The CLI prints the same information from a scenario.

Command line

AIEngine.Cli check <document.json>
AIEngine.Cli explain <document.json> <scenario.json>
AIEngine.Cli import-tree <tree.json> --id <document-id> --out <ai-document.json> [--trace <map.json>]

check prints the accepted document's counts, each behaviour's interval, node count, memory slots and max cost, plus the minimum step budget. explain runs one think on a scenario and prints the decision path. import-tree converts an offline integer decision tree into a format-1 document; trees are compiled offline and never at run time.

Exit codes: 0 done, 1 refused (the refusal code is printed, e.g. AI_FORMAT), 2 usage or file problem.

GameRuntime integration

AiComponent is the only thing that changes the runtime during a session. Its event catalog is declared once, before Init:

EventDirection
ai.agent-add-requested, ai.agent-remove-requestedRequest in
ai.percept-posted, ai.percept-lost, ai.key-postedRequest in
ai.intent-raisedResult out — the owning component translates it
ai.step-done, ai.refusedDiagnostics out

Requests only queue; Update applies them in arrival order, then steps the runtime with the session tick and the configured budget. IsQuiet is true when no request waits, which is when a checkpoint is consistent. Fingerprint() reports tick, state digest prefix, step count and pending count. The component refuses a budget below MaxCost at construction (AI_NOT_QUIET is the checkpoint-refusal code).
