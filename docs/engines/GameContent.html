Purpose

GameContent is the game's data layer: what things exist, what they are made of, what they cost, what station and skill they need and which era they belong to. It is authored once as packs and consumed by several engines through converters, so an item's numbers are not typed twice and cannot disagree.

It owns

Pack manifest and documents, resource and recipe schemas, units and stats, semantic validation, cross-pack library rules, locale tables, conversion reports.

It does not own

Runtime market prices (EconomyEngine), crafting attempts (AlchemyEngine), production scheduling (SimEngine), or combat resolution (CombatEngine).

Nothing is repaired

Every finding is collected in a CatalogReport with a code and location. A pack is accepted whole or refused whole.

Packs and manifests

{ "format": 1,
  "id": "core", "version": "1.0.0",
  "title": "Core materials, energy, money and labor",
  "language": "en", "world": "timeless",
  "genres": ["common"],
  "dependencies": [],
  "license": { "spdx": "CC0-1.0", "provenance": "original", "author": "GameFrameWork" },
  "locales": [],
  "documents": ["resources.json", "recipes.json"] }
  • Pack ids follow a namespace: every id inside a pack starts with <pack>. (CATALOG_ID_NAMESPACE).
  • Dependencies are loaded first and version-checked; cycles are refused (CATALOG_DEPENDENCY_CYCLE).
  • Every document names its pack and format; a document in the wrong folder is refused (CATALOG_DOCUMENT_PACK).
  • Locale documents are declared in locales; their language and ids are checked.

Resources

{ "id": "core.iron-ingot", "name": "Iron ingot", "class": "intermediate",
  "unit": "kg", "origin": "crafted",
  "stack": { "max": 100 },
  "grade": null, "perishable": null, "durability": null, "currency": null,
  "cpc": "4", "tags": ["metal"],
  "properties": { "base-price": 4 } }
FieldRule
classraw, intermediate, product, consumable, currency, energy, fluid, gas, information, labor, population, tool, equipment, unique.
unitA UCUM code from CatalogUnits; must match the class (discrete/continuous rules).
stack, durability, perishable, gradeCapacity, uses and time limits; grade schemes are quality or rarity, compared only within a scheme.
currencyISO-4217 or fictional code; only currency-class resources have one.
cpcCrafting-progress class (a small integer as text) used to reason about tiers.
propertiesString, number or boolean; typed by CatalogSchemas, so a misspelt property is refused.

Recipes

{ "id": "core.smelt-iron", "name": "Smelt iron", "kind": "smelt",
  "inputs":     [ { "resource": "core.iron-ore", "amount": 2 }, { "resource": "core.coal", "amount": 0.5 } ],
  "catalysts":  [], "tools": [],
  "outputs":    [ { "resource": "core.iron-ingot", "amount": 1 } ],
  "byproducts": [], "drops": [],
  "station": { "id": "core.furnace", "level": 1 },
  "skill": null, "environment": [],
  "duration": { "value": 20, "unit": "s" },
  "quality": null, "reverse": null }
  • kind: the closed vocabulary extract, harvest, grow, transform, smelt, refine, craft, assemble, disassemble, cook, brew, combine, upgrade, repair, construct, research, trade, upkeep, consume, decay, loot. Generative kinds may bring a resource into the world without consuming it.
  • tools are tools with uses; a resource cannot be both a tool and an input (CATALOG_TOOL_CONFLICT).
  • drops are chance outputs with an exact fraction; reverse names the disassembly recipe and must be reciprocal.
  • quality = inheritInput or skill; environment tags must be declared by the pack.

Validation

The loader validates in order: schema, model, then semantic rules. Findings are CatalogDiagnostic(Code, Message, Location, Severity); warnings are listed but do not refuse.

GroupExamples
Identity and referencesDuplicates, namespace, unknown refs, visibility across pack dependencies, duplicate ingredients.
Units and valuesUnknown or mismatched units, stack/durability/perishable limits, bad prices, currency rules.
RecipesNo inputs/outputs, bad chance, station/skill level, reverse reciprocity, quality mode, tool conflicts.
Graph and economyUnreachable resources, cycles without a source, non-conserved mass, income-only loops.
Eras and formationsEra spans overlap, tier order, formation equipment exists and is usable, training levels.
BalanceImplausible prices or durations against tier and inputs (warnings).

Codes are in CatalogCodes (CATALOG_*); CatalogRefusedException carries the report.

Library rules

A pack is validated with its dependencies, so it cannot see a sibling genre pack. CatalogLibrary.CheckDuplicates(sets) compares roots: a resource, station or skill with the same display name or the same slug in two different packs is a duplicate (CATALOG_DUPLICATE_NAME, CATALOG_DUPLICATE_SLUG). The shared thing belongs in a pack both depend on — usually core.

Converters and adapters

TargetEntry pointWhat it produces
EconomyEngineCatalogToEconomy.Convert(set, options)Goods and recipes JSON, names and a conversion report. Options set milli-per-price-unit, seconds per period, tuning, locked recipes and recipe ownership.
AlchemyEngineCatalogToAlchemy.Convert(set)AlchemyContent, element/recipe counts and a report listing every reduction.
SimEngineCatalogToSim.Convert(set, ownership)Content/module documents, transformations, stations, vehicles and quality rules.
CombatEngineCatalogCombat.Weapon, Ammo, GroupWeaponSpec, AmmoSpec and a Group with batteries from a formation.
CharactersCatalogCharacters.DocumentA character template document with stat plans and trait weights.

A conversion never invents data: anything it cannot express is reported as ConversionNote — Reduced or Refused — with a code, subject and detail. Read the report before trusting a converted document.

Pack generator and scaffold

  • CatalogScaffold writes a valid new pack skeleton (new-pack).
  • GameContent.Generator/PackGenerator builds the shipped packs from Data*.cs tables; generated packs are then validated like any other.
  • CatalogWriter serialises a model back to canonical JSON, so tools and edits round-trip.

Loading and lookup

var source = new DirectoryCatalogSource("src/GameContent/Packs");
CatalogLoadResult result = CatalogLoader.Load(source, "core");
if (result.Set is null) { foreach (var d in result.Report.Items) Console.WriteLine(d); return; }
CatalogSet set = result.Set;

set.TryResource("core.iron-ingot", out var iron);
set.TryRecipe("core.smelt-iron", out var recipe);
foreach (var item in set.Items) { /* ... */ }

CatalogSet.Packs is dependency-first and ends with the requested pack (the Root). Lookups span the whole set; reference visibility is still enforced per pack.
