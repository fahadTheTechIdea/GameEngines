## 1. Constraints every proposal must respect

Deterministic; integer or fixed-point state (no float in state); counter-based `EngineCommon.DeterministicRoll(seed, stream, index)`; exact checkpoint, replay and digest; bounded sizes; strict JSON, a format bump means format 2 and the old format is refused; passive Init+Update components; headless; one owner per capability; no throwing default arm, no `?? throw`; every result explainable. Measured budgets (from the engine docs): Economy 200 markets x 100 goods about 29-31 ms per period; Relationship 1,000 actors x 20 edges about 1.3-1.6 ms per ordinary step and about 6 ms for a day's first step; WorldEvents 100 regions about 2.7-3.9 ms per step.

## 3. Candidates

Each candidate: what it buys; determinism/integer feasibility; cost against the budgets; format impact; explain trace; acceptance; risk. All costs (est.) unless said.

### G. Shared graph library (`EngineCommon.Graph`)

| Piece | Notes |
|---|---|
| Compact graph (CSR arrays, integer node index, edges sorted by (from, to, id)) | Built from an engine's own ids sorted ordinally. No hash-order iteration anywhere |
| BFS / k-hop reach | replaces the private BFS in WorldEvents `Spread` later |
| Dijkstra with deterministic tie-break | key = (cost, node index); integer costs; binary heap with that composite key. Bellman-Ford exists as the negative-weight/negative-cycle check (Wikipedia says Θ(V·E) worst case, and the final pass detects a negative cycle; R) |
| Min-cost flow, successive shortest path with integer potentials | Wikipedia lists successive shortest path, network simplex, cost scaling (R). Integer capacities give integer flows is standard (own; the page does not state it). Use SSP: simplest, exact, bounded by total supply units |
| Label propagation, **deterministic variant** | Source says the textbook version shuffles the order and breaks ties at random, so it "produces no unique solution" (R). Variant: fixed ascending-id order, ties to the lowest label, max 10 sweeps, start from previous labels. Oscillation of synchronous updates is known generally (own; the page does not discuss it), hence asynchronous in fixed order |
| Fixed-point power iteration (EigenTrust / PageRank style) | Normalise rows (clip negatives, divide by row sum), iterate a fixed count (e.g. 12), values in ppm held in `long`, products in `Int128` as `EconomyMath` already does. Source: EigenTrust normalises local trust, repeatedly multiplies by the transpose and converges for an aperiodic strongly connected matrix (R, Wikipedia). Pre-trusted peers are **not** in that page; they are from the paper (S/U), so treat as own design |
| Bounded counts | degree, weighted degree, triangle count on top-k edges |

Betweenness centrality: **defer**. Exact Brandes needs fractional dependencies (fixed-point is possible but the cost, O(V·E) = 1,000 x 20,000 = 20M per run (est.), is far over the Relationship day-boundary budget unless sampled; sampling needs a seeded source choice and an error statement).

Acceptance: every routine equals an independent oracle on random graphs (big-integer or brute force for small n); same result for any insertion order of the same edges; node/edge bounds enforced; zero allocation growth across repeated calls; Roslyn guard: no `float`/`double`, no `HashSet`/`Dictionary` iteration without a sort. Risk: low; it is a pure library. The only collision risk is the shared `.slnx` and `Directory.Build.props` (see section 5).

### E1. Economy: capacity by gain, then landed-cost routing

**Step A (small, no new concept).** In `Launch`, rank the origin's profitable goods by gain ratio (tie: good id) before spending the capacity, instead of document order. Buys: a route that is full ships the best good. Integer, no format change, cost (est.) +1 sort of at most 100 items per route per period = under 1 ms. Explain: "route R full: shipped grain 120 (gain 310 permille) before salt (gain 90)". Acceptance: the declared order of goods no longer changes the shipped quantities (swap order in the document, same digest of flows); capacity is never exceeded; existing golden hashes change and are re-recorded with a stated reason. Risk: behaviour change breaks existing demo hashes, a stated cost.

**Step B: landed-cost price field.** For each good, one reverse multi-source Dijkstra over routes with edge cost = freight + export/import tariff (the route's cost in the origin's money), source value = destination price; the merchant's gain for an edge uses the best landed price reachable downstream, not just the neighbour's price. Buys: goods cross an intermediate market that does not want them, which is how caravans and rail networks behave in the games that have them; and it fixes weakness (2). Cost (est.): 100 goods x (400 edges x log 200) is about 0.3 M relaxations, roughly 1-3 ms on top of 29 ms. Currency: costs are converted through the rates already used. Cycles of non-negative cost are safe for Dijkstra; shipping is still one hop at a time (a shipment keeps its single route), so **no itinerary state is added**. Format: a document flag `routing` (`direct` | `landed`) and a `maxHops`; format 2. Explain: "ships grain A->B: B pays 410 itself, but C pays 520 landed through B (freight 40, tariff 20)". Acceptance: with `direct` results equal format 1 behaviour exactly; with `landed` a chain with an empty-demand middle ships end to end in the expected periods; never ships when landed gain <= 0; conservation holds (existing 300 random sequences). Risk: merchants may chase a phantom price (price at C changes while goods are in transit); documented, as the current rule already has this with delay.

Evidence of real use: OpenTTD's cargo distribution computes flows over a link graph with a multi-commodity flow job whose path finding is "a slightly modified Dijkstra" (S, the OpenTTD source index and wiki snippets; the algorithm description itself was **not** read). Anno-style "balanced" rule is already adapted. Min-cost flow for the whole routing problem: **adapt later only if** step B shows capacity contention across goods and routes that greedy-by-gain handles badly; measure first.

### E2. Economy: production chains (Leontief)

Document `recipes`: inputs and outputs per period per market-pair set, with a bounded coefficient table; production of a recipe = min over inputs of (stock / coefficient) x rate (fixed coefficients, Leontief); each consumed input adds **derived demand** to that pair's excess demand, each output adds to supply. Source: the input-output model x = Ax + y, solved as (I - A)^-1 y, with a productivity (Hawkins-Simon) condition (R, Wikipedia). We do not need the matrix inverse: a per-period, per-market pass in **topological order** of an acyclic recipe graph (checked at load with Kahn's algorithm, refused if cyclic) is exact and bounded. Buys: scarcity propagates (drought -> flour -> bread), the missing "no production chains" gap in the doc. Cost (est.): recipes x markets, e.g. 50 x 200 = 10,000 small multiplications per period, under 2 ms. Format 2 (shares the bump with E1; see section 5). Explain: "bread output 40 = min(flour 80/2, wood 55/1) -> limited by flour". Acceptance: output equals an independent computation over random acyclic chains; derived demand shows in the input price; conservation of goods per recipe (inputs consumed = coefficients x runs); a cyclic document is refused; wage/pop not added. Risk: **highest design risk**, overlaps the existing `docs/RESOURCE_RECIPE_CATALOG.md` and AlchemyEngine owners (I read only the first 30 lines of the catalog). One owner per capability means the economy must consume the catalog's recipe standard, not invent a second recipe format. Resolve that before coding.

Not adopted for Economy:
- **Newton or other solvers for the price rule.** The page on tatonnement (R) says the Sonnenschein-Mantel-Debreu results mean it does not necessarily reach a unique stable equilibrium; the bounded damped rule is already the safe choice. A Newton step needs the demand Jacobian per pair and adds instability. Reject.
- **General-equilibrium solvers across all goods.** Same objection plus cost. Reject.
- **LMSR.** Hanson's market scoring rule is an automated market maker for prediction markets with a cost function, probability-like prices in (0,1) and a loss bounded by the liquidity parameter (S/R mix: the Prediction market page confirms the bounded-loss and guaranteed-liquidity claims (R); the formula C(q) = b ln sum exp(q_i/b) comes from a Gnosis primer snippet (S) and the b ln n bound I did not find written that way). It prices outcomes that sum to one, not goods; it needs exp and ln, which means a fixed-point table with a stated error. Defer: a bonding-curve price impact for player trades could be revisited if trades need slippage; not now.
- **Taylor rule** for a central bank. The formula is i = pi + r* + a_pi(pi - pi*) + a_y(output gap), coefficients 0.5 (R). The engine has no output gap and no interest rate; the page lists unobservable inputs as a limitation. Defer: a P-controller on money growth toward a price-level target could be a `policy` later; low value now.
- **ARIMA/Kalman forecasting.** Not an engine concern: give agents an EWMA of the price history ring as a percept through the AI bridge if a merchant needs it. Adapt as bridge-level, not engine state. Defer.
- **Bellman-Ford arbitrage across currencies.** Rates are anchored to one reference currency (ECONOMY_ENGINE.md 5.2, 5.4), so cross rates are consistent by construction and a triangular arbitrage cycle does not exist. Reject for currencies. (Bellman-Ford stays in the graph library as the checker for any document that someday states pairwise rates.)
- **LP / network simplex.** Min-cost SSP covers the routing need with integer exactness. Network simplex is faster at scale but harder to make bit-exact in a pivot rule; defer.
- **Agent-based traders with RL.** Learned policies are not exact (section 4). Reject; the AI bridge with utility already provides trader agents.

### R1. Relationship: derived social-graph state (communities, standing, balance pressure)

Three derived pieces, each recomputed at the **day boundary** (where drift, forgetting and gossip already run), each a pure function of edges plus its own saved previous result.

| Piece | Algorithm | Buys | Cost at 1,000 x 20 (est.) | Explain |
|---|---|---|---|---|
| Communities / factions | deterministic asynchronous label propagation over positive-trust edges (G) | `actor.community`, `actor.community_size`; dialogue and AI can say "the miners' circle"; gossip can prefer in-group | 20,000 edges x up to 10 sweeps = 0.2 M ops, under 2 ms | "joined community 17: 7 of 11 trusted neighbours hold it" |
| Standing | fixed-point EigenTrust-style power iteration on the trust axis (G), 12 iterations | `actor.standing` (ppm): an elder vs a pariah, derived from who is trusted by the trusted; replaces the "reputation number" the doc declined to store by making it a **derived fact** | 20,000 x 12 = 0.24 M multiplications, around 1-2 ms | "standing 3.4%: trusted by 12; top contributors ..." |
| Balance pressure (triadic closure) | for each actor, over its top-k trusted neighbours (k = 4, so 6 pairs), if A-B and A-C are positive and B-C is negative (or the reverse mix), add a small dated memory toward the mutual friend/foe, seeded chance, per-day cap | emergent "my friend's enemy is cooling on me" | 1,000 x 6 = 6,000 triad checks, well under 1 ms | "memory 'friend of a rival' -4 on A about C: A trusts B, B dislikes C (Heider triad)" |

Source support. Heider's rule: a triad is balanced when all three links are positive or exactly one is positive (two negative), unbalanced when two are positive and one negative; Cartwright and Harary treat triads as 3-cycles in a signed graph and Harary shows a balanced graph splits into two positive groups joined by negative edges (R, Wikipedia Balance theory). The page gives **no** local update rule and Rapoport's "iterative process" is the only dynamics mentioned, so the pressure rule above is **our design**, not a published algorithm. Davis's weaker clusterability (no cycle with exactly one negative edge) is the better fit for more than two factions (R, same page). Label propagation: weaknesses of randomness stated (R); Louvain is O(n log n) commonly and has badly connected communities and a resolution limit (R); Louvain's greedy modularity gain is order dependent (the page does not say so; **own**), and its aggregation phase makes bounds harder, so label propagation is chosen. Leiden is recommended on that page as the fix and is **deferred**.

Risks. (1) Runaway polarisation from balance pressure: cap per day, per-edge cooldown, memory stacking limit already exist, acceptance test bounds total change over 365 days in a random village. (2) The derived label is state: format 2 saves it (digest changes with it); a pure recomputation without the previous labels would lose stability. (3) The doc's 10.7 "no reputation number" decision is replaced by "no stored reputation; one derived fact", which must be said in the doc. Format 2 fields: `social { communities {...}, standing {...}, balance {...} }`, all present, each with `enabled:false` allowed so a game can opt out.

Acceptance: label propagation equals an oracle and is order independent (insertion order, shuffled ids); standing sums to the stated total within the stated rounding, and a node with no inbound trust has the pre-trust floor; balance pressure never creates a memory the schema did not declare; 365-day random-village bound; exact checkpoint across a day boundary; budget test with a 3x-median margin like the existing ones.

Also in the Relationship family, **adopt as bridge work (no new algorithm):** tell AI agents the opinions they hold of others as percepts (the 10.7 gap), then let AIEngine's utility nodes pick interactions. This matches Prom Week's Comme il Faut idea: authors write reusable social rules and characters carry relationships and memories (S, search snippets and abstracts of McCoy et al.; I did not read the papers). The engine's existing `desire` rules are already volition-rule shaped (own comparison, from the doc); do not build a second action-selection owner. Versu "social practices" (S, abstract only) are **not** pursued.

Deferred in Relationship: Hegselmann-Krause / DeGroot belief dynamics. Search results (S) say the homogeneous HK model converges in finite time to clusters whose limits are equal or more than the bound apart, and that heterogeneous bounds lose the finite-time guarantee; the Wikipedia pages for HK, DeGroot and opinion dynamics returned 404 (U). It needs a new per-actor belief vector, which no current feature asks for; revisit with faction/religion features. Independent cascade / linear threshold: Kempe et al. give a (1 - 1/e) greedy guarantee for influence maximization (S); the engine needs diffusion, not seed selection, and gossip already is a bounded independent-cascade-like process (own). Defer influence maximization; reject greedy-with-simulation inside the runtime (it needs many Monte Carlo runs per decision). Beta reputation (Josang and Ismail) with a forgetting factor: the formulas are the paper's (U: the PDF came back binary; the expected value (r+1)/(r+s+2) is from my knowledge and snippets (S) only). Defer; EigenTrust-style standing plus memories already give a decayed evidence account. Collaborative filtering, Elo/Glicko: no data need; reject.

### W1. WorldEvents: self-exciting hazards (Hawkes) and spatially correlated weather

**Self-excitation.** Hawkes intensity is a baseline plus a decaying contribution from each past event; the branching ratio (integral of the kernel) at or below 1 gives finite families (R, Wikipedia; the page does not cover thinning or ETAS). In integer form with an exponential kernel the sum has a recursive state: per hazard x region keep `excite`, each step `excite -= excite x decay`, each onset in the region (or reach) adds `jump`; onset chance = base rate + excite, capped. O(1) per hazard-region per step, no history list. Buys: aftershocks, outbreak waves, riot clusters. Gutenberg-Richter is already used for severity (R in the engine's own research). Cost (est.): 64 hazards x 100 regions = 6,400 multiplications per step, negligible against 3 ms. Format 2: per hazard `excite { jumpPpm, decayPermille, capPpm }`. Load check: subcritical when `jump / decay` (in consistent units) is below 1 (own derivation for the recursive form; the page states the branching-ratio condition). Explain: "onset 9 permille = base 4 + 5 from quake 3 days ago (excite 5)". Acceptance: long-run onset rate matches the analytic mean base/(1 - branching) within a stated tolerance over many seeds; with jump 0 equals format 1; clustering index (variance/mean of daily counts) above 1 only with excitation; exact checkpoint; all within the 3 ms/step budget.

**Spatial correlation.** Today the regime is global and each region's draw is independent. Proposal: the redraw weights are tilted also by the **neighbours' current weather** (integer weights, a per-zone `spill` permille), so fronts move across links. This is a Markov-random-field-lite (own) and keeps climatology only if the tilt is symmetric or normalised; the existing test "long-run shares equal weights for any persistence" must be extended and may need the tilt to be mean-preserving (a stated risk). Cost: reads neighbour weather, 200 links = trivial. Explain: "redrew rain: 3 of 4 neighbours rain (spill 150)". Rejected alternatives: **Perlin/simplex noise** (floating, and regions are graph nodes, not a grid; a hash-based integer value noise needs coordinates the regions may not have), and **Wave Function Collapse** (the README says deciding whether a bitmap admits others is NP-hard, contradictions end the run with no output and no restart is described (R, mxgmn README), which breaks bounded guaranteed time; it is a tile-adjacency tool, not a climate model). GEV: the distribution has the Fisher-Tippett-Gnedenko extreme-value role and a quantile formula (R, Wikipedia) but sampling needs ln and exp. **Adopt as an offline authoring tool**: derive `tailPpm` rungs and the hydrology's heavy-rain factor from return periods, write the integer table; the runtime stays integer.

**Offline balance harness (W2).** Because a run is a pure function of document and seed, a CLI `simulate --seeds N --years Y` can run N seeds (parallel, each exact) and print percentiles of hazards per year, peak stress, outbreak size, days in each director phase, and which cards never fire. No format change; it is the designer's and the acceptance test's evidence. This is the safe form of "Monte-Carlo forecasting with branch-and-replay": branching inside the runtime would cost a save+open (about 3 + 7 ms) plus steps per rollout at 100 regions (est. 100 ms or more per rollout), so runtime lookahead is **deferred**; offline use costs nothing at play time.

Director research: RimWorld storytellers differ in pacing curve and difficulty is separate (the engine's own earlier reading; wiki gives no formulas). Left 4 Dead: a search snippet says the pacing creates "peaks and valleys" with intensity estimated per player from damage and incapacitation, and says the course of the curve is not explicitly designed (S, an arXiv summary I did not open); Booth's slides themselves came back as binary (U). The Riedl and Bulitko survey of drama management / experience management (AI Magazine, S for the abstract; the PDF was binary, U) frames the problem as coherent narrative vs player agency. Nothing read justifies replacing the stress/phase director with a search or RL manager; planning (HTN/GOAP) of plots: **defer** (AI_ENGINE.md already says planners are unbounded without a depth limit and hard to predict).

Disease: network SIR/percolation/agent-level contact models would need individuals; the engine's regional compartments with link coupling already are the metapopulation form (the metapopulation page (R) is ecology and does not mention epidemics; the compartmental-models page (R, truncated) lists spatial, interacting-subpopulation SEIR and network SIR sections I could not read). Keep. Hazard flood routing on the graph and wildfire cellular automata: the wildfire page (R) mentions Rothermel spread equations and does not mention cellular automata or percolation, so I have **no read source** for CA wildfire; **defer**, and when needed the existing hop-falloff Spread plus the hydrology river store is the place.

## 4. Machine learning and LLMs: the determinism position

Reject learned models **in the running simulation** unless they are exact integer programs. Reasons.

1. Float inference is not promised to be bit-identical across compilers, CPUs and builds. Gaffer on Games: answer is "yes, if" with the same compiler and instruction set, strict IEEE mode, restricted operations and a performance cost; "incredibly naive" to expect identical results from arbitrary float code (R). The repo's own SpatialEngine doc also records that Godot's pathing classes use float and promise nothing on determinism.
2. Lockstep/replay needs the number and order of random calls to match; the AI engine already applied that lesson (AI_ENGINE.md, citing the Age of Empires paper it read).
3. A runtime model that cannot explain itself violates the explain-trace rule.

What is allowed. (a) **Offline training, quantised export**: a small decision tree, gradient-boosted trees or a tiny MLP trained offline, thresholds and weights stored as integers in strict JSON, evaluated with integer arithmetic and fixed iteration counts. In practice a tree **is** a behaviour tree/utility table the AI engine already runs, so export to AIEngine JSON and add no inference engine (own reasoning; no source read on quantised inference, so no claim about its error). (b) Behaviour cloning from logged human play, same export. (c) **MCTS/UCT as a decision planner**: four phases and the UCT formula w/n + c·sqrt(ln N / n) are standard, with a Total War: Rome II campaign AI use named on the page (R, Wikipedia); it can be exact with a counter-based roll and a fixed iteration count, but it needs a forward model of the game (a clone), costs iterations x model step, and plays poorly where "trap" lines exist (R). **Defer** to a planner for Diplomacy or Combat decisions with its own bounded budget; not an economy/relationship/world-events need. (d) **Influence maps**: Dave Mark's modular maps (AI_ENGINE.md read it in an earlier pass; not re-read now) belong to SpatialEngine as a sensor service; defer until a spatial feature needs one.

LLM / generated content: **offline authoring aid only, never in the runtime**. Why: nondeterministic output cannot be replayed; cost and latency per call; content cannot be validated at load if it appears at run time; and checkpoint/replay would need the model's output stored as input. Evidence from a shipped-tool announcement: Ubisoft's Ghostwriter produces first-draft barks, offers writers pairs to choose from, lets them edit or scrap, and is stated not to be used for cinematics or lore; it drew criticism from developers (S, trade-press snippets; I did not read the GDC talk; later shipped use not found). Recommended pipeline for this repo (own design): LLM or tool proposes a draft **as a strict JSON file or locale table** -> `check` CLI of the owning engine (schema, bounds, refusal codes) -> `coverage` for locale gaps -> human review of every line and number with the explain/simulate output beside it -> merge as ordinary data -> provenance note (tool, date, reviewer) in the doc's evidence, not in the runtime. Numbers (rates, prices, weights) stay human-set and are checked by the W2 harness; generated text carries content-warning and licensing review as the dialogue engine already requires.
