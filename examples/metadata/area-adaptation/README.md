# Required-space orientation examples

These are framework fixtures, not a configured game. The existing bounded
`LayoutAdaptation` owner tries `AreaRotation` over an explicitly permitted range.
The source +90/-90 degree area split cannot fit both complete source reservations;
the nearest permitted zero-degree split can. The weighted case retains the
original elevation-derived density. Each fixture keeps all seven metadata nodes,
two source-sized physical sites (84 m² footprint and 192 m² reservation each),
four logical constituent nodes and the required interface route. It does not
claim physical geometry for the four logical constituents.

The output retains the failed source attempt, accepted signed setting, original
intent and density, and exact work ledger. Program/cut targets, wrong strategies,
out-of-range rotation and finite attempt/work exhaustion refuse. Neither source
geometry nor required minima are resized. Rotation controls allocation guidance,
not the facing of source structures. No recipe is automatically opted in.

Use the existing `generate-metadata` CLI with a variant's recipe/catalog and a
new directory. Checked packets are `generated/area-adaptation-checked/*`.
[Evidence](../../../docs/evidence/2026-10-29-area-landforms-verification.json)
covers current API/CLI/Node checks and initial browser rendering. Source/history
edits, rollback and checkpoints pass; owner composition and all-genre world
acceptance remain open. Godot is deferred.
