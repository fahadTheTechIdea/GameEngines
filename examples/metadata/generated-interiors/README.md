# Generated connected interiors

Framework examples of the shared topology → placement → interior assembly flow.
The engine grows exact source room modules from an arrival anchor and a declared
connection graph. Each room retains its required equipment. Per-room positions,
doorway coordinates and corridor polylines are generated by C#.

`Interiors` selects game-authored room and connection kinds in a floor/container.
The assembly owner derives doors from real shared boundaries, retains corner
piers and builds inward wall strips. Complete width-qualified paths must avoid
source equipment and closed walls. Unlinked shared edges remain closed.
Necessary contact checks run during partial placement and complete assignment;
final wall, opening and route qualification still runs against all contents.

The original four inputs cover six rectangular rooms, that program rotated23°,
eight larger rectangular rooms and six hexagonal modules. The controlled
[size/shape study](size-shape-range/study.json) additionally declares6/12/16/24
rooms for both source shapes, with zero or one extra graph edge. All sixteen
attempts retain exact sources, required fixtures, deck and original budgets.

All16 declared cases now generate, including the four24-room programs with every
required fixture and graph edge. Graph-guided growth supports at most128 demands
per stage; unrestricted search retains its16-demand limit. A valid connected
graph or independent exact anchors are mandatory for that growth capacity.
The interior assembler's2–32-room limit and prescribed-placement limits remain
separate contracts. Complete walls share the existing256-exclusion surface
capacity. Larger hierarchies require explicit stages and working interfaces;
they must not be silently split, relabeled or truncated. Count errors report
expanded count, execution mode and applicable maximum. Budget failures remain
explicit refusals rather than proof of universal infeasibility.

Example doorway width is1.2m, wall thickness0.12m, approach depth0.6m and traveler
radius0.2m. These are authored test values, not engine defaults or building law.
Independent checks retain all464 physical sources,224 openings and448 directed
routes in the16 accepted cases, with934752 segment-to-wall/fixture edge checks.
Native replay owns complete floor coverage and work-accounting validation.

Current physical assembly uses convex planar modules. Exterior entrances and
wall-aware outside routing, chunk indexing and population derived from generated
interiors use the same metadata owners. Independent floors/domains are supported
through explicit transitions; they do not imply continuous volumetric geometry,
concave-floor synthesis, physics, door artwork or a complete game. See the
[current metadata contracts](../../../docs/WORLD_METADATA.md) for exact scope.
Godot and artwork remain deferred.
