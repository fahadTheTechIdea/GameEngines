# Physical ownership redesign

These are reusable framework inputs, not a configured game. They demonstrate how
actual complete-source packing and required travel can change ownership design.
Godot and artwork remain deferred.

`network-request.json` and `authored-request.json` preserve an impassable terrain
cut and all complete nested programs. Their first ownership division separates
the required journey. The existing physical-feedback owner exhausts that exact
component context, then considers another declared cut assignment. Ordinary
generation qualifies every complete source and outward/return path.

`packing-request.json` retains full 70-by-10-meter catalog sources and their
required modules. A wider region fits them without resizing anything.
`multi-cut-request.json` preserves two exact destination pins, rejects a proposed
partition that conflicts with them, and changes an internal cut while keeping
the root cut. It retains all 20 nodes and 12 original physical sources.

`joint-request.json` combines terrain-derived counts, complete program choices,
ownership and physical travel. The unchanged habitat equation determines six
complete discoveries and six original 2.4-meter markers per final region. Counts
are remeasured from actual accepted habitat, not manually reduced after failure.
The selected source worlds equal their unchanged declared feasible alternative.

Use `MetadataRegionalOwnershipPlanner.Plan(request)` followed by
`MetadataRegionalWorldGenerator.Generate(definition)`, or the existing
`generate-derived-regional-world` command. Required input catalogs, recipes,
terrain and finite search choices are included in each request. No game wizard,
mockup or art profile is needed.

Each physical attempt identifies its exact ownership context. Contexts retain
requested/selected cut vectors, whole masks and separate component domains;
component ordinals cannot transfer between changed masks. Rejected planning and
physical candidates remain diagnostics. Source edits, saved history and rollback
replay the complete design. `exhausted-request.json` is an intentional refusal
control: protected destinations cannot satisfy the required connected journey.

Only declared finite axis alternatives are searched. Attempt, work, geometry and
route-candidate limits remain hard, distinct from finite exhaustion. Source-only
impossibility is not retried as geometry. This does not finish arbitrary boundary
design, broader game variety/scale, developer object editing or streaming.
