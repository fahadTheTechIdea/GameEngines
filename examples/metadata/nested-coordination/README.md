# Coordinated nested programs

These framework inputs instantiate the same complete program inside one or two
20×10 parent envelopes. Each parent requires two 2×2 children. Source child
spacing is 1m; the consumer requires 2m. The engine keeps parent frames and the
preferred first child at each parent's center, then reconsiders the incompatible
second child before source commitment.

The one-parent case retains four nodes/three physical members in two attempts.
The two-parent case retains seven/six in three attempts. Every program instance,
source dimension and accepted source node remains exact. Node-identity clauses
prevent constraints from leaking between instances sharing local demand names.

Use each directory's `recipe.json` and `catalog.json` through `generate-metadata`.
No specific game, artwork or Godot project is required. This is finite purposeful
candidate selection, not nearest continuous packing or route-dependent repair.
