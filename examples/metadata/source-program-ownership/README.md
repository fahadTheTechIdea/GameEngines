# Qualified source programs and downstream content

These framework inputs exercise the same C# owners across upstream choices,
accepted terrain/allocation habitats and separately added consumer choices.
They are technical composition controls, not a complete game or genre profile.

- `recipe.json`/`catalog.json`: source composition rejects oversized programs,
  qualifies two unchanged14×6m sites, retains their original journey and derives
  three0.4m discoveries from its actual440m² allocation.
- `consumer-recipe.json`/`consumer-catalog.json`: the same source choices remain
  inherited while a separate consumer choice selects only added discoveries.
- `region-recipe.json`/`region-catalog.json`: source physical qualification rejects
  its first region, chooses the second2400m² component and preserves all source
  members/journeys while adding two required discoveries.

Use `WorldMetadataGenerator.Generate` or `GenerateFilesAsync`; public CLI form:

```text
generate-metadata examples/metadata/source-program-ownership/recipe.json examples/metadata/source-program-ownership/catalog.json <fresh-output>
```

`AnalyzeProgram` retains original qualified source composition and accepted
habitat bindings while consumer physical positions remain unbound. Source changes
must be authored upstream; conflicting consumer rules refuse. Nested ownership
SpatialContext plus population sources is still an open integration. Godot and
artwork are deferred.
