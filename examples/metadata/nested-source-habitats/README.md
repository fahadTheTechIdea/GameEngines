# Nested source habitats inside automatic ownership

These reusable framework inputs compose computed ownership, three nested source
regions/local allocations per owner, complete compounds/modules, actual upstream
program choices and terrain-funded additional content. They are technical controls,
not a complete game or a finished world-design/genre profile.

- `request.json`: two complete source worlds plus all21allocation-funded discoveries.
- `source-only-request.json`: complete sources with honest zero independent
  consumer selections backed by actual upstream region composition.
- `allocation-edit-request.json`: lower source coverage grows actual alpha
  allocations and requires32complete discoveries, preserving every original body.
- `mixed-source-request.json`: oversized300m alternatives remain in the catalog;
  complete shared search rejects them and selects declared12m source programs.
- `terrain-rotation-request.json`: protected terrain and23degree ownership
  orientation change actual source geometry and all required population remains.

Use `MetadataRegionalOwnershipPlanner.Plan` followed by
`MetadataRegionalWorldGenerator.Generate`/`PublishAsync`. Public CLI form:

```text
generate-derived-regional-world examples/metadata/nested-source-habitats/request.json <fresh-output>
```

The source owns `UsePlacementBoundary`, terrain intent, region-demand minima,
relative/area local layouts and complete choices. Consumer habitat overrides
refuse. Required discoveries use actual accepted allocation area/800m² and a
declared longest-initial-edge grammar, preserving0.4m bodies and source journeys.
No map grid or city-specific rule is imposed. Broad world-design/scale, locks,
streaming, artwork and Godot remain open/deferred.
