# Generated partitions from required program anchors

Reusable framework inputs, not a configured game. `recipe.json` selects
`AnchorBisection` with no authored cuts or grid. The C# engine derives a recursive
tree from required program anchors, clips it to the generated terrain region and
qualifies complete source-sized structures, reservations, access and an interface
route. Both complete structures and their seven total nodes are retained within
the example's explicit partial-world scope.

`alternative-recipe.json` starts with an unsuitable grid and permits the same
anchor-driven strategy; the existing selector records the grid rejection before
accepting the generated tree. Both recipes use `catalog.json`. Neither requires
a game name, city model, mockup, artwork or Godot.

Command: `generate-metadata <recipe.json> <catalog.json> <new-output-dir>`.
The result includes canonical inputs, generated tree provenance, exact allocations,
semantic geometry and the JavaScript schematic. Missing/insufficient content or
disconnected generated spaces refuse rather than shrinking or moving protected
anchors. The algorithm is one deterministic local subdivision strategy, not a
whole-world intent planner or an optimal-layout guarantee.

See [contract](../../../docs/WORLD_METADATA.md#generated-anchor-partitions) and
[verification](../../../docs/evidence/2026-10-29-anchor-partitions-verification.json).
