# Capacity-driven content and physical placement

The recipe requests 25 game-authored rest spaces. Each reusable camp supplies 10, so the engine creates three camps. Each camp retains its two declared constituent station points. One direct-part placement binding expands into all three source-sized footprint demands; terrain qualification and the existing network planner connect the resulting destinations.

Changing `visitors` to 31 generates four camps and eight constituent points through the same catalog and placement template. No footprint is resized and no required part is dropped. These are game-authored quantities, not measured facilities or real population requirements.

`generate-metadata` consumes the adjacent recipe and catalog. The current review packet is `generated/capacity-world-final/schematic.html`. Select a camp and expand Content capacity to inspect demand, per-instance capacity, generated count and source identity. The exported document replays capacity membership and physical allocation on read/export.
