# Coupled regional space and habitat content

This framework reference uses the common C# owners. It is not a game template or
a claim that all world-generator stages are complete. Godot and artwork are deferred.

`request.json` defines a 336×224m shared terrain, its original protected560m²
exclusion, three complete reusable compounds and two regional round trips. Each
compound retains both source modules, every buffer/detail/equipment member,
source surroundings and its85%minimum open-ground requirement. The supplied
catalog also requires at least four discovery targets per region; actual suitable
habitat funds one target per5000m². Every target has a whole2×2m body,3×3m
reservation and a required two-way route with the original0.4m actor width.
These are game-authored reference rules, not framework defaults.

The request's explicit `Coupling` policy starts from unchanged catalog minima.
The existing regional owner partitions actual spatial demand, qualifies anchors,
binds each real regional surface/boundary and remeasures complete content. Only
reproduced area/clearance/weight requirements are accepted. Every iteration and
its work/habitat identity remains in `OwnershipPlan.CouplingPlan`; exhaustion,
cycles and budget excess refuse. `PopulationSource.Context.UsePlacementBoundary`
explicitly binds an unbound source habitat mask. It also retains that source
habitat plan in the generated consumer. Conflicting source/consumer masks refuse.

The baseline converges in two iterations, generating62nodes/59physical bodies
and14actual discovery targets. All19round trips retain their full width.
Larger complete compound envelopes, reversed demand fields and a moved protected
terrain exclusion are qualified
counterfactuals in the native test. Source sizes, minima and budgets are preserved.
Capacity convergence alone is not packing or path proof: ordinary generation
must still place every body and validate every journey before publication.

The public command is:

```text
generate-derived-regional-world examples/metadata/coupled-population-world/request.json <new-output-directory>
```

The resulting packet contains complete world metadata, the derived definition,
regional packets and a JavaScript/SVG schematic. JavaScript displays saved engine
coordinates; it does not choose counts, regenerate or relocate content.
