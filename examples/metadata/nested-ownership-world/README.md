# Nested world programs inside automatic ownership

This reusable framework request declares an irregular300×180m domain, protected
terrain and three outer location programs. The engine derives their ownership,
three terrain-selected semantic regions inside each, and complete local content.
Nine source-sized compounds retain eighteen nested modules and every required
local and inter-region journey. The33nodes/27physical bodies form a technical
composition control; they are not a finished city or game.

`SpatialContext` explicitly binds each null-boundary intent template to computed
ownership. Six local allocations use automatic area grammars; three use region-
relative power diagrams. These computational boundaries do not create streets or
force a world grid. The catalog, purposes, clearances and layout choices are
authored content. Initial region choices are explicitly deferred; accepted worlds
have real complete bindings and full physical qualification.

The SDK uses `MetadataRegionalOwnershipPlanner.Plan` and
`MetadataRegionalWorldGenerator.Generate`. The public CLI is
`generate-derived-regional-world request.json <new-output>`. Existing source-driven
regional sessions support attributed edits, failure preservation, source-history
restore and exact rollback. No mockup, artwork or Godot project is required.

Verified source-size, terrain and ownership-orientation controls preserve all
members. A mixed-catalog control retains the oversized300m source in its catalog,
rejects it and selects complete declared alternatives rather than resizing it.
Full context/population-source composition, broad design/scale, locks and streaming
remain open; Godot deferred.
