# Protected gameplay population

This reusable framework input combines physical population, eligible source
variation, protected spaces and a required collectible journey. It is not a
configured game and needs no mockup or artwork. The ordinary `generate-metadata`
API/CLI consumes `recipe.json` and `catalog.json`.

The complete program has 20 nodes: 11 physical sources and eight separate logical
badge members. Two entrances and the actual resource have four directed physical
paths. A persistent capability is acquired at the resource before the exit can
be used; the progression model also requires a return. This is generation
metadata, not runtime inventory or NPC behavior.

The source owns anchored spawn/sightline reservations and a resource interaction
area. Tagged detail cannot occupy those spaces or close the physical passages.
Changing the detail seed selects eligible source forms while preserving every
semantic identity and the complete unrelated source packet. Removing the resource
obligation or substituting decorative content refuses instead of dropping it.

Only the one-square-meter resource footprint has an assigned material. The other
2179 square meters remain explicitly unresolved. They are not filled with gardens
or counted as completed detail. Unsupported 3D visibility, artwork, motion and
Godot/runtime behavior remain deferred.
