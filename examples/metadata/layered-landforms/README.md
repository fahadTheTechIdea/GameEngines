# Generated terrain with the full layered program

These framework examples reuse the required seven-compound catalog and retain
all fourteen structures, seven yards, fourteen caches and eighteen derived
landscape members. Terrain is generated by the shared heightfield owner: 13 × 11
samples, 15-meter sample intervals, an irregular domain, and a protected additive
ridge/valley. Sampling cells do not create streets or object-placement cells.
There are no planar patches replacing the generated field.

Flat, ridge and valley keep the same source dimensions, counts, routes and work
limits. Each yields 61 nodes, 60 physical members, 82 directed paths and 143
canonical chunk members. Every sampled height and triangle grade is checked
independently; the ridge/valley maximum grade is about 0.08376 under the unchanged
0.1 rule. The suitable-region minimum stays 25,000 m². Shared conservative geometry
broad phases allow the full program through the existing terrain-demand work
budget; an identical previously failing input now exports successfully.

`blocked` is intentionally infeasible: the two-meter ridge leaves only 24,975 m²
of suitable terrain. Generation refuses without a published world. A separate
1.8-meter ridge probe also exposed unresolved disconnected-space/centroid failures;
these three gentle cases do not prove adaptive synthesis around steep terrain.
Positions and density controls still follow the declared reusable grammars.
This is not a claim of expressive-range, full terrain composition, occupied-world
coverage, artwork, a complete game, or owner design acceptance.

Use the current `generate-metadata` CLI with each recipe/catalog and a new output
directory. Checked successful outputs are `generated/layered-landforms-checked/*`.
[Verification](../../../docs/evidence/2026-10-29-area-landforms-verification.json)
records exact checks, inputs, failures and hashes. Godot remains deferred.
